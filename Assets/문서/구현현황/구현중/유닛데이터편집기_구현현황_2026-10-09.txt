유닛 데이터 편집기 구현현황 (2026-10-09)
════════════════════════════════════════════════════════════════════════
작성 목적: units.json / skills.json 과 유닛 프리팹을 한 창에서 편집하고 양방향으로 맞추는 도구
(Tools(new)/유닛/유닛 데이터 편집기)를 만든 내용을 기록한다. 가중치/시야인지반응/스킬/애니메이션 슬롯
구현현황 문서와 같은 관례(✅구현/🔶부분/❌미구현 + "다음 우선순위")를 따른다.

배경
- 옛 JsonToUnitPrefabConverter("JSON -> 유닛 프리팹 생성")는 프리팹을 새로 만들어 덮어썼다. 오래 안 쓰는
  사이 JSON과 프리팹이 34곳 어긋났고(기사형·근접 탱커 스킬 목록 3개 vs 1개, 근접 탱커 maxHp 180 vs 300,
  아처형 정밀 사격 damageMultiplier 10 vs 1 등), 프리팹에만 있던 값(deathVfxPrefab 15개, corpseSprite 12개,
  보스 골렘 손, 기사형 무기 포즈 튜닝)은 재실행하면 사라질 상황이었다.
- 사용자 결정(2026-10-09): 창으로 대체한다. 6가지 동작 — ① 열면 JSON을 파싱해 프리팹과 같은/완전한 데이터로
  제공 ② 참조 할당을 인식해 JSON 갱신 ③ +/-로 유닛 추가·제거 ④ Save를 눌러야 반영 + 저장 안 하고 나갈 때
  피드백 ⑤ 선택한 유닛만 프리팹화 ⑥ 프리팹에서 JSON으로 역변환. "프리팹이 다 최신"이라고 확정해 프리팹→JSON
  가져오기를 1순위로 했다. 사망 연출·손·무기 소켓도 창에서 설정 가능하게 한다.
- 런타임은 units.json/skills.json을 읽지 않는다(Addressables Data/units·Data/skills 주소는 있으나 읽는
  코드 없음). 런타임의 진실은 프리팹, JSON은 작성·교환용.

■ 첫 실행 절차 (마이그레이션 — 처음 한 번)
────────────────────────────────────────────────────────────────────────
1. Tools(new)/유닛/유닛 데이터 편집기를 연다. 상단에 "프리팹과 값이 다른 유닛 N개" 안내가 뜬다(예상: 대부분).
2. [다름 N개 전부 프리팹 값으로 가져오기] — 작업 사본만 바뀐다(파일은 아직 그대로). 비교 탭에서 유닛별로 확인.
   JSON에 없는 프리팹이 있으면 unitClass를 'Monster'로 둔 채 추가되니 확인해서 고친다.
3. [JSON 저장]. 이때 파일 서식이 한 번 정리된다: units.json은 폐기된 animatorController 줄만 사라지고
   (+ 새로 생기는 death/bossHands/무기 포즈/skillOverrides), skills.json은 키 순서가 다른 10개 항목이
   정규 순서로 정리되고 "isPiercing": false 한 줄이 생략된다. git diff로 확인 후 커밋.
4. [검증]을 눌러 전부 ✓인지 확인한다. ✗가 나오면 Console의 상세를 본다.

■ 다음 우선순위 구현 후보
────────────────────────────────────────────────────────────────────────
1. **Unity에서 실행 확인(미실행)** — 아래 체크리스트. 지금까지는 컴파일 + 순수 로직 하니스까지만 확인했다.
2. **유닛 이름 변경(rename)** — 지금은 미지원. typeName은 프리팹 파일명·Addressables 주소(Units/{이름})·
   WaveData.unitTypeName이 모두 의존한다. 지원하려면 AssetDatabase.RenameAsset + 주소 변경 + WaveData 문자열
   치환 + UnitVisualDefinition.unitTypeName을 한 번에 처리해야 한다.
3. **옛 도구 정리** — Disposable/유닛/ 보스 골렘 도구 2종(BossGolemHandSetupTool·BossGolemVisualScaleFix)은
   편집기의 bossHands 블록·visualScaleIgnoresFootprint 필드로 대체됐다. 편집기 확인 후 지운다.
   UnitVisualDefinition의 컨텍스트 메뉴 LoadDataFromJson(footprint/engageDistance/stats/skills만 덮어쓰는
   부분 갱신)도 편집기와 중복이라 위험하다 — 같이 정리 후보.
4. **인형 줄·십자가 장식의 JSON화** — 지금은 프리팹 전용으로 보존(근접 탱커·야생 몬스터 A·인형 기사의
   LineRenderer 4개 + MarionetCross). 값으로 풀면 LineRenderer 설정까지 스키마가 커져서 보류(사용자 확정).
5. **Undo/Redo** — 작업 사본이 일반 C# 객체라 Ctrl+Z가 없다(변경 버리기로 전체 되돌리기만 가능). 필요하면
   작업 모델을 ScriptableObject + SerializedObject로 바꾼다.
6. **스킬 이름 변경 시 애니메이션 슬롯** — 스킬 이름을 바꾸면 슬롯 이름도 바뀌어, 이미 꽂은 클립은 옛 슬롯에
   남는다(AnimationSlotSync가 클립 있는 옛 슬롯을 지우지 않고 경고). 클립 이동 지원 여부 결정.
7. **하니스 보관** — 순수 로직 하니스(dotnet run, 41건)는 저장소 밖에서 돌렸다. Assets/Tests는 Assembly-CSharp
   안이라 Editor 코드를 못 부른다. 저장소에 두려면 Unity가 무시하는 "Harness~" 폴더 + 상대경로 csproj로 둔다.

■ 장별 구현 현황
────────────────────────────────────────────────────────────────────────
✅ 요구 1 열기: JSON·프리팹을 둘 다 읽고 유닛별 상태(동기화됨/다름 n/프리팹 없음/JSON 없음) 표시, 비교 탭.
✅ 요구 2 참조 할당: [AssetRef] 필드는 ObjectField, 고르면 에셋 이름이 JSON 값. 이름이 겹칠 때만 이름#GUID.
✅ 요구 3 추가(＋, 다른 유닛 복제 가능)/제거(－, WaveData 참조 경고, 프리팹은 저장 시 휴지통).
✅ 요구 4 저장 게이트: 작업 사본 → [JSON 저장](Ctrl+S). hasUnsavedChanges로 닫을 때 Unity가 저장/버리기를 묻고,
   스크립트 재컴파일에도 작업 사본이 살아남으며, 디스크 JSON이 밖에서 바뀌면 알려 준다.
✅ 요구 5 체크한 유닛만 프리팹 적용(이미 같은 유닛은 건드리지 않음, 적용 전 요약 확인창).
✅ 요구 6 프리팹→JSON 가져오기(체크한 유닛, 또는 다름 전부).
✅ 사망 연출(deathVfx·corpseSprite)·visualScaleIgnoresFootprint·무기(스프라이트·기준각·5방향 포즈)·보스 손
   (좌/우 스프라이트·위치·반전·정렬순서 + 수치 5개)을 JSON 스키마에 추가하고 창에서 설정 가능.
✅ 스킬 모델: 전역 정의 + 유닛별 skillOverrides(체크한 필드만 다른 값). 프리팹→JSON 때 자동 통합(무손실).
✅ 서식 보존: 읽고 다시 써도 원본과 같은 모양(CRLF·2칸·원시값 배열 한 줄·소수형 필드 "7.0"·0은 "0").
✅ 검증 버튼 / 스키마 드리프트 경고(SkillData·UnitVisualDefinition에 필드가 생겼는데 편집기가 모를 때).
🔶 프리팹 제자리 갱신: JSON 스키마에 있는 값만 쓰고 나머지는 보존. 블록이 JSON에 없어도 spriteLibrary·bossHands
   컴포넌트는 지우지 않는다(안전 규칙) — 그래서 적용 뒤에도 남는 차이가 생길 수 있고 결과 메시지가 알려 준다.
❌ 유닛 이름 변경, Undo/Redo, 인형 장식 JSON화 (위 "다음 우선순위" 참고).

■ 사용자 확인으로 정한 판단

- 스킬 모델: 전역 정의 + 유닛별 오버라이드(실제로 갈라진 건 몬스터 공용 3종의 baseCooldown·hitEffectPrefab뿐).
- 손은 JSON화(bossHands), 인형 장식은 프리팹 전용 보존.

■ 내가 정한 내부 판단 (요청·문서에 없어서)
────────────────────────────────────────────────────────────────────────

- 참조를 못 찾으면 기존 프리팹 값을 유지하고 경고(찾지 못해 비워 버리는 사고 방지).
- 빈 WeaponSocket 10개(스프라이트 없음, 기본 포즈)는 JSON에 올리지 않고 프리팹에 그대로 둔다.
- 옛 컨버터(JsonToUnitPrefabConverter)는 제거(같은 일을 비파괴로 하는 창이 대체).
- polish: 폐기된 animatorController 키는 읽기만 하고 쓰지 않는다(첫 저장 때 사라짐).

■ 플레이 확인 체크리스트
────────────────────────────────────────────────────────────────────────
A. 창 열기: 유닛 16개 목록과 상태 배지, Console 오류 없음, "스키마 점검" 경고 배너 없음.
B. [다름 전부 프리팹 값으로 가져오기] → 작업 사본만 바뀌고(저장 버튼 활성) 비교 탭에 차이가 보인다.
   저장 → git diff 크기가 위 "첫 실행 절차"의 예상 범위인지.
C. 저장 후 모든 유닛이 "동기화"로 바뀌는지. [검증] → 전부 ✓. (✗면 Console 상세 — Reader/Writer 비대칭 의심.)
D. 스탯 하나를 고친 뒤 창을 닫을 때 저장 확인창이 뜨는지, 취소/저장/버리기가 각각 맞게 동작하는지.
E. 저장 → 체크 → [JSON → 프리팹 적용]: 값이 바뀌고 기존 deathVfx·corpseSprite·무기·보스 손·인형 장식이 그대로인지
   (프리팹 git diff로 확인). 애니메이션 슬롯에 꽂은 클립이 유지되는지.
F. 참조 필드(예: hitSpark)를 ObjectField로 바꾸면 JSON에 이름으로 기록되는지, 이름이 겹치는 에셋은 이름#GUID인지.
G. 보스 골렘: 유닛 탭에 bossHands(좌/우 손) 블록이 보이고, 값을 고쳐 적용하면 프리팹 손에 반영되는지.
H. 기사형: 무기 poses(튜닝값)가 JSON에 담기고, 다른 무기 유닛은 poses가 "기본 포즈 사용"인지.
I. ＋ 유닛 추가(다른 유닛 복제) → 적용 → 프리팹 생성·Addressables 등록(주소 Units/{이름}, 라벨 Units)·애니메이션 슬롯 생성.
J. － 유닛 제거: WaveData 참조 경고가 뜨는지, "프리팹도 제거"를 고르면 저장 때 휴지통으로 가는지.
K. 편집 중 스크립트를 수정해 재컴파일해도 작업 사본이 유지되는지.
L. 창을 연 채 JSON을 밖에서 수정(git pull 등)하고 창에 포커스를 주면: 변경 없을 땐 자동 재로딩, 작업 중이면 배너.
M. 스킬 개별 값: 근접 탱커 '육중한 내리찍기'의 baseCooldown 체크(5), 전역 쿨다운(7)을 바꿔도 근접 탱커는 5 유지.
