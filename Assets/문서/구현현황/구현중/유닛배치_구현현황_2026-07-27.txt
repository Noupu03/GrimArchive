유닛 배치 시스템 기획서 — 구현현황 (2026-07-27)

이 문서는 같은 날 앞서 작업한 "점령 관련"(OccupationState/방 색칠/이동 인접제한, 시야인지반응
구현현황과 별개 트랙) 및 "야생 몬스터 A"(RoomConfinedMovement 등)와 겹치는 인프라를 그대로 재사용
했다 — Room/roomGrid/allRooms(GameSession.BuildRoomGrid, 전체 층 순회로 이미 확장돼 있었음)가 이번
구현의 기반이 됐다.

태그
  ✅ 구현       — 문서 규칙이 코드에 정확히 있고 실제 게임 루프에서 자동 발동.
  🔶 부분/근사  — 동작은 하지만 문서가 수치/공식을 안 줘서 자체 판단으로 채웠거나 단순화함.
  ❌ 미구현     — 사용자 확인대로 이번 범위에서 제외(스텁).

■ 2장. 기본 관리 단위
════════════════════════════════════════════════════════════════════════
✅ 2.1 유닛 — (기존 시스템) 유닛은 이미 개별 ScriptableObject 개체로 관리되고 있었다. 이번에 "현재
   소속 방"(Unit.currentRoom)만 신규 추가.
✅ 2.2 다중 선택 — (기존 시스템) InputManager.selectedUnits가 이미 "여러 개체에 동일 명령 일괄 적용"
   방식으로 구현돼 있었다(부대로 묶지 않음, 문서 요구사항과 정확히 일치) — 이번에 새로 만든 것 없음.

■ 3장. 방 소속
════════════════════════════════════════════════════════════════════════
✅ 방 소속(신규) — Unit.currentRoom을 UnitFunction.OnUpdate가 매 프레임 실제 위치 기준으로 동기화한다
   (GameSession.roomGrid 타일 단위 조회 → 바뀌었으면 이전 방에서 제거, 새 방에 등록). "이동 완료
   이벤트"가 아니라 위치 기반 상시 동기화라서, 4.3장 "도착하면 소속 변경"뿐 아니라 9장이 보류한
   "생성 직후 배치"에도 부작용 없이 자연히 대응된다(스폰 코드를 따로 건드릴 필요가 없었음). 배회
   몬스터(WildMonsterBehavior)는 9장 보류 항목이라 동기화 대상에서 제외 — currentRoom이 항상 null로
   남는다.
✅ 방의 정보(최대 인구수/현재 인구수/소속 유닛 목록) — Room.MaxPopulation/CurrentPopulation/
   ContainedUnits로 구현. "연결된 문/연결된 다른 방"은 별도 필드를 안 만들고 기존 CreateMap.Floor.gates
   (Gate 리스트)를 그대로 조회해 쓴다(중복 데이터 방지).

■ 4장. 유닛 이동
════════════════════════════════════════════════════════════════════════
✅ 4.1 이동 명령 — InputManager 우클릭 핸들러가 문서 순서(유닛 선택→목적지 지정→인구수 확인→미확인 시
   취소→경로 탐색→이동→도착→소속 변경)를 그대로 따른다. 인구수 확인은 신규, 나머지 단계는 기존
   이동 시스템(AIMovementHelper/PlayerCommandFSMState) 그대로 재사용.
✅ 4.2 이동 방식 — (기존 시스템) 순간이동이나 전용 연출 없이 기본 이동 시스템만 사용 — 원래부터 그랬고
   이번에 손댈 필요가 없었다.
✅ 4.3 방 도착 이후 — 도착 후 방 내부 자유 이동은 기존 탐색 이동 그대로(별도 제약 추가 안 함 — 야생
   몬스터 A의 RoomConfinedMovement와 달리 이 시스템 유닛은 방을 나갈 수도 있어야 하므로 의도적으로
   구속하지 않음). 소속 방 변경은 3장의 SyncRoomAffiliation이 담당.
✅ 4.4 이동 중 명령 변경 — 별도 구현 없이 기존 "우클릭 재입력 시 playerMoveTarget 덮어쓰기" 동작으로
   전부 자연히 충족된다: 새 목적지 재지정(재클릭), 이동 취소·기존 방으로 복귀(원래 방을 다시 클릭),
   다른 유닛과 재지정(선택 변경 후 재클릭) 모두 기존 메커니즘 그대로. "행동 지침 변경"은 아래 참고.

■ 5장. 방별 인구수
════════════════════════════════════════════════════════════════════════
🔶 5.1 최대 인구수 — 문서에 공식/수치가 없어 사용자 확인대로 "방 크기(청크 수) 비례" 공식 채택:
   GameSession.PopulationPerChunk(=4, 2026-07-27 세션 중 사용자 요청으로 6→4 조정) × 그 방의 청크 수
   (BuildRoomGrid가 순회하며 계산). 밸런스 확정값 아님, 자리표시자. 인구수 자체가 몬스터(플레이어
   진영, IsPlayerMonsterFaction) 전용이라는 점도 같은 세션 중 사용자가 정정 — Room.CurrentPopulation과
   InputManager의 이동 명령 계산 둘 다 인류·야생 몬스터는 제외하고 플레이어 소속 몬스터만 합산한다.
🔶 5.2 유닛별 인구수 — 기본 유닛 인구수 1(문서 명시값, 2026-07-27 세션 중 사용자 요청으로 2→1 조정)
   그대로 적용, Unit.populationCost/UnitVisualDefinition.populationCost/units.json populationCost로
   전부 배선 완료. "대형 유닛·특수 유닛은 더 높은 인구수" 조항은 스키마상 유닛별로 얼마든지 다른 값을
   줄 수 있게 이미 준비돼 있지만, 현재 4종 유닛이 전부 footprint 1×1이라 실제로 1이 아닌 값을 가진
   유닛은 아직 없다(대형 유닛이 추가되면 그때 개별 수치만 정하면 됨).
✅ 5.3 인구수 초과 처리 — InputManager가 우클릭 시점에 목적지 방의 (현재 인구수 + 이동해올 유닛들의
   인구수 합)이 최대 인구수를 넘는지 먼저 확인하고, 넘으면 경고 로그 남기고 선택된 유닛 전체의 명령을
   취소한다(일부만 자동으로 이동시키는 기능 없음 — 문서 요구사항 그대로). 이미 그 방 소속인 유닛은
   합산에서 제외(재이동 아님).

■ 6장. 자동 배치 제한
════════════════════════════════════════════════════════════════════════
✅ (확인만) 유닛 자동 분배·자동 인구수 맞춤 배치 기능은 원래부터 존재하지 않았다 — 새로 만들지 않는
   것 자체가 이번 구현의 일부.

■ 7장. 전투와의 연계
════════════════════════════════════════════════════════════════════════
❌ (사용자 확인, 스텁) "전투 시작 시 문이 닫혀 방 이동 제한", 증원/퇴각/강제 문 개방은 이번 범위에서
   제외 — 문서 자체도 "유닛 배치 시스템과 분리하여 추후 구체화"라고 명시했고, 방 단위 "전투 시작/문
   개폐" 개념 자체가 아직 코드에 없어(개별 유닛의 CombatFSMState만 있음) 별도 전술 시스템 설계 시
   같이 다룰 것.

■ 8장. 적용 범위
════════════════════════════════════════════════════════════════════════
✅ (자동 충족) 4~5장 구현이 이동 "목적"(방어/공격 투입/탈환)을 구분하지 않고 모든 방 이동 명령에
   공통 적용되므로, 방어 병력 배치/방 사이 병력 이동/미점령 방 공격 투입/전초기지 탈환 투입 전부
   자동으로 같은 규칙을 받는다. 전투 시작 이후의 증원·퇴각만 7장대로 별도 규칙(미구현) 대상.

■ 9장. 보류 항목
════════════════════════════════════════════════════════════════════════
✅ (준수) 배회 몬스터(야생 몬스터 A) — 방 소속 동기화 대상에서 명시적으로 제외(WildMonsterBehavior
   체크), 인구수 시스템과 무관하게 기존 RoomConfinedMovement로만 동작.
✅ (준수) 유닛 생성 직후 배치 — 스폰 코드를 전혀 건드리지 않았다. SyncRoomAffiliation이 매 프레임
   상시 동작이라 스폰 직후에도 다음 프레임에 자연히 올바른 방으로 등록되지만, "생성 위치/생성 가능
   인구수/생성 대기 상태"를 별도로 판단하는 로직은 의도적으로 만들지 않았다(문서가 보류 항목으로 명시).

■ 미구현/미결정 남은 것
════════════════════════════════════════════════════════════════════════
- 문서 2.1장 "행동 지침"(behavior directive) — 유닛 배치 시스템이 새로 정의하는 개념이 아니라 이미
  존재해야 하는 별개 속성으로 서술돼 있으나, 코드 전체를 뒤져도 그런 시스템 자체가 없다(존재하지 않는
  것으로 보임). 다중 선택으로 일괄 설정한다는 §2.2 요구사항은 그 시스템이 생기면 자연히 적용 대상이
  되겠지만, 지금은 구현할 실체가 없어 손대지 않았다 — 별도 기획/문서가 나오면 그때 연결.
- 5.1장 방 최대 인구수 공식(청크당 6)과 5.2장 대형 유닛 인구수 차등값은 전부 밸런스 확정값이 아닌
  자리표시자 — 실제 밸런싱 단계에서 조정 필요.
- 7장 전투 연계(문 닫힘/증원/퇴각/강제 개방)는 완전 미구현.

■ 사용자 확인이 필요했던 판단 (전부 2026-07-27 확인 완료)
════════════════════════════════════════════════════════════════════════
- Q1. 방 최대 인구수를 무엇으로 계산할지(문서에 수치/공식 없음) — → A. "방 크기(청크 수) 비례 공식
  사용" 채택. GameSession.PopulationPerChunk = 6 → 같은 세션 후반에 사용자 요청으로 4로 재조정.
- Q5(후속, 같은 세션). 인구수 제한 적용 대상 정정 — → A. "정확히는 플레이어 진영의 몬스터만 포함"
  (인류 제외는 원래 방침대로, 야생 몬스터도 제외 필요 — Room.ContainedUnits에 야생 몬스터가 직접
  들어가는 기존 스포너 코드 때문에 처음엔 "인류만 제외"로 잘못 구현했던 걸 IsPlayerMonsterFaction
  기준으로 수정).
- Q6(후속, 같은 세션). 기본 유닛 인구수 점유량 — → A. 처음 문서값 2 그대로 적용했다가, 사용자 요청으로
  1로 재조정(공식 문서 5.2장 원문도 "2를 기준" → "1을 기준"으로 함께 수정).
- Q2. 기존 "점령"(자기 점령방+인접방만 이동 가능, 몬스터 전용) 제한과 이번 인구수 체크를 어떻게
  합칠지 — → A. "둘 다 유지" — 몬스터는 인접방 제한과 인구수 체크를 모두 통과해야 이동 가능. 인류는
  기존처럼 인접방 제한은 없고(테스트용) 인구수 체크만 받음.
- Q3. 우클릭 이동 목적지를 "정확한 클릭 타일" vs "그 타일이 속한 방 전체"로 바꿀지 — → A. "지금처럼
  정확한 클릭 타일 유지" — 우클릭 UX는 안 바꾸고 인구수 체크만 추가.
- Q4. 이번 구현 범위(인류/몬스터 포함 여부, 7장 포함 여부) — → A. "인류/몬스터 둘 다 적용, 7장(전투
  중 문 닫힘)은 이번엔 스텁" — 추후 전술 시스템 몫으로 명시적으로 남김.
