머리 위 대사 연출(말풍선) 구현현황 (2026-10-19)
════════════════════════════════════════════════════════════════════════
작성 목적: 유닛 행동을 캐릭터 대사처럼 설명하는 머리 위 텍스트 연출 시스템의 구조·연결 지점·한계를 기록한다. 사용자 요청: "캡슐화해서 유닛 객체 머리 위에 텍스트 연출을 띄우는 시스템… 후퇴, 도주, 상황판단 등을 실제 캐릭터 대사처럼".
근거: 후퇴도주 명세서 4-3장(텍스트 연출 예시)·7-3장(대사와 실제 정보의 구분). 다시 손댈 때는 이 문서부터 확인한다(다른 구현현황 문서와 같은 관례).

■ 핵심 규칙
────────────────────────────────────────────────────────────────────────
· 대사는 연출일 뿐 전파·사망·도주 정보가 아니다(명세서 4-3·7-3장). 이 모듈은 게임 상태를 읽기만 하고 바꾸지 않는다 — 대사로 개인 지도·가중치·정신력·도주 확정 등을 만들지 말 것. "OO가 없는데?"는 미집결 사실 표현일 뿐 사망·도주 단정이 아니라서 문구에 "죽었다/도망쳤다"를 넣지 않는다(테스트로 고정).
· 새 대사가 필요하면 SpeechId + SpeechCatalog 항목을 추가하고, 행동 시스템에서 SpeechSystem.Say(유닛, id) 한 줄만 부른다. 표시·순위·쿨다운은 모듈이 처리한다.
· 비주얼이 없거나 세션이 없으면(테스트·사망·미생성) Say는 조용히 false를 돌려준다 — 호출부는 반환값을 쓰지 않는다.

■ 구조
────────────────────────────────────────────────────────────────────────
Assets/Script/Unit/Speech/
  SpeechCatalog.cs  — SpeechId(16종)·SpeechTone(Calm/Alert/Fear/Panic)·SpeechEntry(문구 후보·어조·표시 시간·순위·유닛/전체 쿨다운) + 상황별 문구 목록
  SpeechMath.cs     — 순수 함수: 유닛 이름→종류명("사제_7_5_0"→"사제")·한글 조사({S가}→이/가)·문구 선택·긴 문구 2줄 나눔·덮어쓰기/쿨다운/페이드 판정
  SpeechSystem.cs   — 단일 진입점 Say(유닛, id, 대상 이름, ignoreCooldown). 유닛별 + 전체 쿨다운 기록(여러 명이 동시에 외치는 합창 방지), Enabled 토글, 테스트용 Random01/Now
Assets/Script/Unit/Visual/UnitSpeechBubble.cs — 월드 공간 TextMesh + 배경 스프라이트. UnitVisual이 처음 필요할 때 만들어 들고 있고(StatusLabel·체력바와 같은 방식으로 부모 localScale 역산, 유닛 상단 +1.0), 순위가 같거나 높은 대사만 덮어쓴다. 끝나기 0.4초 전부터 페이드, 안개 방의 유닛이면 숨김(체력바와 같은 기준), 시간은 게임 시간(Time.deltaTime — 일시정지 중엔 멈춘다).
연결부: UnitVisual.ShowSpeech/SetSpeechHiddenByFog/ClearSpeech, UnitGenerate.ShowSpeech(+ 매 프레임 안개 숨김 갱신, 사망 연출 시 지움), BottomMenuBar debug "대사 연출" 블록(ON/OFF 토글 + 선택 유닛에 대사를 차례로 띄워 보는 테스트 버튼).
Assets/Tests/SpeechSystemTests.cs — 16건(이름·조사·문구 선택·2줄 나눔·덮어쓰기·쿨다운·페이드·목록 완전성·명세서 문구·세션 없는 유닛 안전성).

■ 연결 지점 (SpeechSystem.Say를 부르는 곳)
────────────────────────────────────────────────────────────────────────
 FleeSystem.ConfirmFlee            개인 도주 확정 → "난 살아남을거야!!!!"/"흐아아악"/"더는 못 싸워!!" (조우 충격으로 확정이면 "도망쳐야 해!")
 FleeSystem.ApplyEncounterShock    +2 → "상대하기 버겁다…" / +3 신규 공황 → "몸이 움직이지 않아…" (※ Lv→대응 단계 표가 비어 조우 충격 자체가 휴면이라 지금은 안 나온다)
 MentalSystem.OnFleeWitnessed      파티원 도주를 직접 목격한 사람 → "어디가!!!"/"이봐! 돌아와!"
 PartyRetreatSystem.Begin          파티 후퇴 시작 → 리더가 이유를 말함(평균 HP 기준/평균 정신력 기준 문구가 다르다)
 RetreatSystem.EvaluatePersonalRetreat  개인 후퇴 시작
 PartyRetreatSystem.UpdateArrivals 거점 첫 도착자 → "여기서 숨 좀 돌리자."
 PartyRetreatSystem.TickRest       휴식 완료 → 탐험 재개/출구 이동 문구
 Party.Rally (CheckRallyComplete)  미집결자가 있으면 리더 → "OO가 없는데?" (한 명씩, 같은 대상 30초 쿨다운)
 Party.Rally (집결 시작)           리더 → "모여! 정비한다."
 TrapPartySystem.OnTrapDiscovered  함정 최초 발견자 → "함정이다! 조심해!"
 PartyDeathSystem.ApplyDeathInfo   파티원 사망을 직접 확인한 사람(전파 수신자는 말하지 않음) → "이럴 수가…!"
 PartyCoreReportSystem.OnCoreDiscovered  코어 발견자 → "코어다! 여기가 목표야."

■ 문구의 출처
────────────────────────────────────────────────────────────────────────
· 명세서 문구(그대로): "상대하기 버겁다…"·"몸이 움직이지 않아…"·"도망쳐야 해!"(4-3장), "난 살아남을거야!!!!"·"흐아아악"·"어디가!!!"·"OO가 없는데?"(7-3장).
· 나머지 문구는 행동의 이유를 캐릭터 말투로 설명하도록 새로 쓴 연출 문구다(문서 규정 아님 — 말투·표현은 기획이 바꿔도 된다. SpeechCatalog만 고치면 된다).
· "도망쳤나보군.."(수색 후 추정)은 미집결자 수색 실행이 없어 연결하지 않았다.

■ 한계 / 미검증
────────────────────────────────────────────────────────────────────────
· 컴파일(오류 0·경고 71)과 순수 로직 하니스 16건 통과까지만 확인했다. 에디터가 열려 있어 Unity 테스트·플레이는 못 돌렸다 — 실제 화면에서 위치·글자 크기·배경 크기·겹침(상태 라벨/체력바와의 간격)·안개 숨김은 눈으로 확인이 필요하다. 조정 상수는 UnitSpeechBubble 맨 위(OffsetAboveTop·글자 크기 SizeOf·PadX/PadY·FadeSeconds)와 SpeechMath.Wrap(maxChars=12).
· TextMesh 경계는 텍스트를 바꾼 직후 갱신이 늦을 수 있어 배경 크기를 처음 3프레임 동안 맞춘 뒤에 보여 준다.
· 말풍선은 유닛당 하나다. 순위가 낮은 대사는 높은 순위가 떠 있는 동안 버려진다(대기열 없음).
· 사람 눈 플레이 확인 방법: debug 메뉴 "대사 연출" 블록 → 인류 선택 → "대사 테스트"를 누를 때마다 16종이 차례로 뜬다. 실제 흐름은 후퇴·도주 확인 블록(정신력 -30 등)으로 이어서 본다.

■ 다음 우선순위 후보
────────────────────────────────────────────────────────────────────────
1. 플레이로 크기·위치 튜닝(위 상수).
2. 몬스터/플레이어 유닛의 대사(지금은 인류 행동 위주 — 연결 지점이 전부 인류 시스템이다).
3. "도망쳤나보군.."(수색 후 추정) — 미집결자 수색 실행이 생기면.
4. 대사 대기열이나 말풍선 겹침 처리(여러 유닛이 가까이 모여 말할 때).
