코어 · 점령 구현현황 (2026-10-19 ~ 20)
════════════════════════════════════════════════════════════════════════
작성 목적: `Assets/문서/공식문서/코어, 점령/`(설계명세서 v0.2 = 구현 대상, 핵심본 = 기획 의도 참고, 순서도 drawio/html, 회의록 10.19)의 구현 범위·구조·판단·한계를 기록한다. 사용자 요청: "코어 점령 먼저 구현하고, 검증한 다음에, 도주 후퇴 + 코어 점령 같이 테스트". 다시 손댈 때는 이 문서부터 확인한다(다른 구현현황 문서와 같은 관례).
사용자 확정: (10-19 "기본값") 범위 A(코어 상태·방 확보)+B(점령 파티·거점), C는 코어 파괴·잔해 반출 기록까지, D 제외. 점령 파티는 1층 코어 활성화 이후 등장(자동 편성이 없어 debug 스폰). 완전 활성화 전 일반 웨이브는 현행 유지. 기초 시설 = 방 경계의 인류 문(목책은 후속), 예정 방어 시설 = 자리표시자. 코어는 층당 단일(보스방).
(10-20 재점검 후) ① 방 소유 모델은 **문서 문구대로 분리**(플레이어 확보와 인류 거점은 별개 상태) ② 미확인 방 진출 **기본 ON 유지**(→ 2026-10-21 사용자 요청으로 **기본 OFF**로 변경) ③ 패배 조건은 **알림+로그만** ④ 재점검에서 나온 버그·미흡 4~8번 수정 + 리팩토링.

■ 문서가 뒤집은 것 (이전 구현과 달라진 점)
────────────────────────────────────────────────────────────────────────
· 코어 체력 0 = 막타 진영으로 방 소유권 전환 + 반피 회복 → **코어는 파괴 상태로 그 자리에 남고 방 소유권은 바뀌지 않는다**(수복 명령으로만 돌아옴). `OffenseProcessor.OnCoreDestroyed` 삭제, 파괴 순간은 `CoreSystem.OnCoreDestroyed`.
· 플레이어 방 확보 = 코어 파괴 → **방 클리어**(적대 생존 0, 은신 포함, 플레이어 유닛이 서 있는 방)로 `RoomClearSystem`이 0.5초마다 판정한다. 방 소유(`Room.RoomFaction`)를 바꾸는 곳은 `OffenseProcessor.ApplyRoomOwnership` 하나이고 호출자는 `RoomClearSystem`뿐이다.
· **인류 거점은 방 소유와 별개 상태다**(`Room.BaseStage` None/Basic/Defense). 기초 시설 완공이 플레이어의 확보·건설 권한을 제거하지 않는다(1-1·12-2장) — 이전 구현은 완공 시 방을 인류 소유로 바꿔 플레이어가 그 방에 새로 건설하지 못했다. 방 윤곽선(색 + 펄스)은 플레이어 방 확보 전용이다(2026-10-22 사용자 결정 — 확보와 거점이 같은 테두리 채널을 써서 구분이 안 됐다). 거점은 현장 상징물·방 정보 패널·알림으로 보인다.
· 코어는 **최초 완전 활성화(보스 처치 + 코어 방 클리어 + 플레이어 실행) 전엔 누구도 공격 불가**. 활성화 이력은 파괴·수복과 무관하게 유지.
· 플레이어 몬스터는 코어를 공격하지 않는다(우클릭 → 일반 이동). 플레이어의 코어 행동은 완전 활성화·수복뿐(코어 정보 패널 버튼).
· 인류 웨이브 승리 = 코어 파괴 → **잔해를 주워 던전 밖으로 반출**. 운반자가 죽으면 그 자리에 잔해가 다시 놓이고 퇴각이 풀린다.
· 인류 점령 = **점령 파티가 기초 시설(방 쪽 인류 문)을 완공**해 기초 거점이 되는 것. 점령 파티는 코어 처리 우선 규칙(집결·이동 계획 폐기)에서 빠진다.

· 공사 정지 — `OccupationSystem.IsConstructionDisturbed`: 파티원 누구든(방 무관) `PartyEngagement.IsEngaged`(전투 상태·경계·합류 대기·적 인지)거나 마지막 피격 후 2초(`OccupationMath.HitPauseSeconds`, 자리표시자) 안이면 기초·방어 공사 틱이 통째로 안 돈다(진행도·현장 연출 유지). 이전엔 "공사하는 방에 있는 파티원"만 봤고 피격 자체는 보지 않았다. 피격 시각은 `UnitCombatState.lastHitTime`(신설)에 `UnitFunction.MarkHit`이 남긴다 — 물리·마법 피해, 정신 피해, 직접 피해 세 경로 전부.

■ 플레이 확인 체크리스트 (debug 메뉴 "코어 · 점령 확인" 순서)

 1. 코어 클릭 → "불완전 활성화"와 활성화 불가 사유(보스 생존/적 남음)가 뜨는지. 보스방 클리어 후 [완전 활성화]가 뜨는지(빠르게: debug "코어 강제 활성화" — 활성화 순간 링 3개가 코어에서 방 끝까지 퍼지고 벽 밖으로 번지지 않는지). 플레이어 몬스터를 보낸 미확보 방 라벨에 "남은 적 N"이 뜨고 클리어하면 확보되는지.
 2. "코어 강제 파괴" → 생산 건물 진행도가 멈추고, 건설/함정/문 재설치가 막히고 이유별 안내가 뜨는지. [수복(돌 300)] → 같은 진행도에서 재개되는지. 확보하지 않은 방에서 건설하면 "확보하지 않은 방" 안내가 뜨는지.
 3. 활성화된 코어를 인류(웨이브 파티)가 공격하는지, 파괴 후 잔해를 한 명이 줍고 파티가 퇴각해 출구로 나가면 웨이브 성공 로그가 나오는지. 활성화 전에는 공격하지 않는지. 기절한 유닛이 코어/문을 때리지 않는지.
 4. "점령 파티 스폰 (1층 입구)" → 현장 자리에서 기초 시설을 짓고(방 라벨 "인류 거점 건설 N%"), 문이 인류 소유가 되고, 완공 후 집결 → 다음 방 진출. 코어를 알게 돼도 멈추지 않는지.
 5. 파티 HP/정신력을 낮춰(debug 후퇴 블록) 후퇴 → 방어 거점 > 기초 거점 순, 방어 거점으로 정한 방은 휴식 뒤 방어 시설 공사 후 재출격, 모든 거점을 잃으면 던전 밖 철수. 점령 파티가 전멸하면 전방 거점이 초기화되는지.
 6. 플레이어가 인류 거점 방의 인류 문을 모두 파괴 → 거점 상실 로그와 천막·방어 시설 철거(윤곽선은 원래 변하지 않음), 후퇴 중이던 파티가 다른 거점으로 바꾸는지.
 7. 잔해를 든 인류의 정신력을 낮춰 개인 도주를 확정시키면(debug 후퇴 블록) 그 자리에 잔해가 다시 놓이고 파티가 퇴각을 풀어 다시 줍는지, 도주한 본인은 줍지 않고 출구로 가는지.
 8. 점령 파티 거점 건설(기초·방어 공통): 근접(팔라딘·전사·도적·몽크)이 문·목책 바로 앞 1칸에, 원거리(마법사·궁수·사제·주술사·음유시인)가 천막 바로 옆 1칸에 각자 다른 칸으로 서서 움직이지 않는지(게이트가 여럿이면 근접이 고르게 나뉘는지, 근접이 많아 문·목책 곁이 차면 천막 쪽으로 가는지). 건설 중 파티원 한 명이라도 맞거나 적을 발견하면 방 라벨/정보 패널의 "건설 N%"가 멈추고, 교전·경계가 끝난 뒤 일꾼이 자기 칸으로 돌아와 같은 진행도에서 재개되는지.
