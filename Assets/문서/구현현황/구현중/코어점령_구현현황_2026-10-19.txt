코어 · 점령 구현현황 (2026-10-19 ~ 20)
════════════════════════════════════════════════════════════════════════
작성 목적: `Assets/문서/공식문서/코어, 점령/`(설계명세서 v0.2 = 구현 대상, 핵심본 = 기획 의도 참고, 순서도 drawio/html, 회의록 10.19)의 구현 범위·구조·판단·한계를 기록한다. 사용자 요청: "코어 점령 먼저 구현하고, 검증한 다음에, 도주 후퇴 + 코어 점령 같이 테스트". 다시 손댈 때는 이 문서부터 확인한다(다른 구현현황 문서와 같은 관례).
사용자 확정(2026-10-19 "기본값"): 범위 A(코어 상태·방 확보)+B(점령 파티·거점), C는 코어 파괴·잔해 반출 기록까지, D 제외. 점령 파티는 1층 코어 완전 활성화 이후 등장(자동 편성 로직이 없어 debug 스폰). 완전 활성화 전 일반 웨이브는 현행 유지(새 귀환 규칙을 만들지 않음 — 후퇴·도주·전멸로만 끝남). 기초 시설 = 방 경계의 인류 문(목책은 후속), 예정 방어 시설 = 자리표시자 오브젝트. 코어는 층당 단일(보스방), 분할 코어는 구조만.

■ 문서가 뒤집은 것 (이전 구현과 달라진 점)
────────────────────────────────────────────────────────────────────────
· 코어 체력 0 = 막타 진영으로 방 소유권 전환 + 반피 회복 → **코어는 파괴 상태로 그 자리에 남고 방 소유권은 바뀌지 않는다**(수복 명령으로만 돌아옴). `OffenseProcessor.OnCoreDestroyed` 삭제, 파괴 순간은 `CoreSystem.OnCoreDestroyed`.
· 플레이어 방 확보 = 코어 파괴 → **방 클리어**(적대 생존 0, 은신 포함, 플레이어 유닛이 서 있는 방)로 `RoomClearSystem`이 0.5초마다 판정해 확보한다.
· 코어는 **최초 완전 활성화(보스 처치 + 코어 방 클리어 + 플레이어 실행) 전엔 누구도 공격 불가**. 활성화 이력은 파괴·수복과 무관하게 유지.
· 플레이어 몬스터는 코어를 공격하지 않는다(우클릭 → 일반 이동). 코어에 대한 플레이어 행동은 완전 활성화·수복뿐(코어 정보 패널 버튼).
· 인류 웨이브 승리 = 코어 파괴 → **잔해를 주워 던전 밖으로 반출**. 운반자가 죽으면 그 자리에 잔해가 다시 놓이고 퇴각이 풀린다.
· 인류 점령 = 코어 파괴가 아니라 **점령 파티가 기초 시설(방 쪽 인류 문)을 완공**하는 것. 완공하면 방이 인류 소유가 되고 거점(기초 거점)이 된다.

■ 자리표시자·해석 (문서가 정하지 않아 제가 정한 것 — 틀리면 정정)
────────────────────────────────────────────────────────────────────────
· 코어 HP 1000(기존 유지)·파괴 전 피해 회복(기존 5초 뒤 초당 10, 파괴된 코어는 회복 안 함), 수복 비용 돌 300(`CoreSystem.RestoreStoneCost`).
· 건설 작업량 기초 150·방어 150 인-초(`OccupationMath.BasicWorkUnits/DefenseWorkUnits`, 현장 자리에 선 인원 1명이 초당 1 — 5명이면 30초). 거점 정원 = 처음 출격 인원, 주둔 거점 상한 2(`GarrisonBaseCap`).
· 인류가 기초 시설을 완공하면 이미 플레이어가 확보한 방도 인류 소유가 된다. 플레이어가 그 방을 다시 클리어하면 플레이어 소유로 돌아오고 거점 자격(BaseStage)은 잃지만 인류가 지은 문·표식은 남는다. **게임 시작 방(1층 시작방)도 예외가 아니다**(점령 파티가 입구에서 거기부터 짓는다).
· 인류 문으로 바뀐 문은 플레이어 몬스터가 지나가려면 파괴해야 한다 — 시작방 문이 인류 소유가 되면 플레이어가 갇힌다.
· 방어 거점 지정은 정원 가득 + 상한 여유 시 "가장 가까운 유효한 기초 거점"이며, 파티가 하나뿐인 지금은 첫 기초 거점이 곧 방어 거점으로 정해진다(후퇴·휴식 때 방어 시설을 짓는다).
· 활성화·수복 시 그 코어를 이미 아는 인류에게 "미처리 코어"로 알린다(발견 이벤트가 최초 1회뿐이라 활성화 전에 본 코어가 영영 보고되지 않는 문제를 막으려는 해석 — 인류의 인지 경로를 문서가 정하지 않음).
· 잔해: 코어 파괴 시 코어 곁에 생성, 파티 중 한 명이 주워 운반(한 파티 운반자 1명), 운반자 사망 시 사망 위치 근처 재배치(확률 낙하는 수치가 없어 만들지 않음), 던전 밖 이탈(후퇴·도주 포함) 시 반출 기록.

■ 알려진 한계 / 미검증
────────────────────────────────────────────────────────────────────────
· **Unity 플레이로 확인하지 못했다.** dotnet build(오류 0·경고 71) + 순수 판정 하니스 44건 + Unity 에디터 로그에서 컴파일 오류 없음까지만 확인. 건설 현장 자리·진행도, 문 소유 전환 후 통행, 웨이브 인수인계, 잔해 줍기·반출, 방어 시설 공사, 후퇴 목적지 선택은 플레이 확인이 필요하다.
· 점령 파티가 안전 정보 없이 진출하는 기본 동작(AllowUnknownAdvance=ON)은 문서(12-1장)와 다르다. 끄면 위험도 기록이 생길 때까지 진출하지 못한다.
· 웨이브 파티와 점령 파티가 같은 방에서 만나면 각자 구동기가 따로 돈다(상호작용 검증 안 함).
· 점령 파티 첫 목표 방이 플레이어 확보 방이면 전투 후 건설한다(1층 시작방 포함).

■ 플레이 확인 체크리스트 (debug 메뉴 "코어 · 점령 확인" 순서)
────────────────────────────────────────────────────────────────────────
 1. 코어 클릭 → 상태 "불완전 활성화", 활성화 불가 사유(보스 생존/적 남음)가 뜨는지. 보스방 클리어(골렘 포함 처치) → 방이 플레이어 확보되고 [완전 활성화] 버튼이 뜨는지. (빠르게: debug "코어 강제 활성화")
 2. "코어 강제 파괴" → 생산 건물 진행도가 멈추고, 건설/함정/문 재설치가 막히고 안내가 뜨는지. 코어 클릭 → [수복(돌 300)] → 생산이 같은 진행도에서 재개되는지.
 3. 완전 활성화된 코어를 인류가 공격하는지(웨이브 파티), 파괴 후 잔해가 생기고 한 명이 줍고 파티가 퇴각하며 출구로 나가면 웨이브 성공 로그가 나오는지. 활성화 전에는 코어를 공격하지 않는지.
 4. "점령 파티 스폰 (1층 입구)" → 방 안에서 현장 자리로 모여 기초 시설을 짓는지, 문이 인류 소유가 되는지(플레이어 몬스터가 못 지나가는지), 완공 로그·거점 설명(후방/전방) → 집결 → 다음 방 진출.
 5. 파티 HP/정신력을 낮춰(debug 후퇴 블록) 후퇴 → 방어 거점 > 기초 거점 순으로 가는지, 휴식 뒤 방어 거점으로 정한 방이면 방어 시설을 짓고 나서 재출격하는지, 모든 거점을 잃으면 던전 밖으로 나가는지.
 6. 플레이어 몬스터로 인류 거점 방을 다시 클리어 → 플레이어 소유로 돌아오고 후퇴 중이던 파티가 다른 거점으로 바꾸는지.
