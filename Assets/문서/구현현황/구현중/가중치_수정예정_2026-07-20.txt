[발견 경위]
19장 표는 흔적 유형별 기본 흥미도를 "시체/흔적=10, 전멸 흔적=25"로 나누고, 바로 아래 공식은
"시체, 흔적 흥미도 = 시체, 흔적 기본 흥미도 + 원인 대상 위험도 단계 보정값(0/+5/+10/+15/+20)"이라고만
적혀 있다 — 표 헤더 문구만으로는 이 보정값이 "전멸 흔적"에도 적용되는지 "시체/흔적" 카테고리
한정인지 불명확하다.

실제 코드(PersonalMapKnowledge.RegisterObject)는 시체만 보정을 받고 전멸 흔적은 고정값을 쓴다:
```csharp
if (tags.Any(t => t.Contains("WipeoutTrace")))
{
	_objectInterest[objectId] = WeightMath.WipeoutTraceBaseInterest;  // 고정 25, 보정 없음
}
else if (tags.Any(t => t.Contains("Corpse")))
{
	_objectInterest[objectId] = WeightMath.CorpseTraceInterest(causerStage);  // 10 + 보정
}
```

[판단 — 보정 적용 쪽으로 확정, 사용자 확인 2026-07-20]
같은 문서 13-2장("전멸 흔적 발견 전역 반영값")이 이미 정확히 동일한 구조로 전멸 흔적에 보정을
적용하고 있다:
```csharp
// WeightMath.cs, 기존 코드
public const float WipeoutTraceGlobalBase = 25f;
public static float WipeoutTraceGlobalReflection(DangerStage causerStage) => WipeoutTraceGlobalBase + DangerStageBonus(causerStage);
```
`WipeoutTraceGlobalBase(25f)`와 `WipeoutTraceBaseInterest(25f)`가 같은 값이고, 보정 공식
(`+ DangerStageBonus(causerStage)`)도 동일 — 13-2장이 이미 "전멸 흔적 + 위험도단계 보정"이라는
같은 패턴을 쓰고 있으므로, 19장의 "시체, 흔적 흥미도" 공식도 전멸 흔적에 대칭적으로 적용되는 게
문서 전체의 일관성과 맞다고 판단했다. `CauserStage`는 전멸 흔적 스폰 시점(GameSession.
CheckPartyWaveState)에 이미 넘겨받고 있어 데이터도 준비돼 있다.

[제안 코드]
1) WeightMath.cs — 19장 전용 함수 신설(13-2장 WipeoutTraceGlobalReflection과 공식이 완전히 같아
   그 함수를 그대로 위임 호출한다. 다만 호출 의미(19장 타일 흥미도 vs 13-2장 던전 전역 위험도
   반영값)가 서로 다른 개념이라 이름은 따로 둔다):
```csharp
// ─────────────────────────── 19장. 시체 / 흔적 흥미도 ───────────────────────────
public const float CorpseTraceBaseInterest = 10f;
public const float WipeoutTraceBaseInterest = 25f;

public static float CorpseTraceInterest(DangerStage causerStage) => CorpseTraceBaseInterest + DangerStageBonus(causerStage);

// 2026-07-20: 전멸 흔적도 시체/흔적과 동일하게 원인 대상 위험도 단계 보정을 받는다(사용자 확인) —
// 13-2장 WipeoutTraceGlobalReflection과 공식이 완전히 같아(둘 다 25 + DangerStageBonus) 그 함수를
// 그대로 재사용한다. 호출부(19장 타일 흥미도)와 13-2장(던전 전역 위험도 반영값)의 의미가 달라
// 이름만 별도로 둔다.
public static float WipeoutTraceInterest(DangerStage causerStage) => WipeoutTraceGlobalReflection(causerStage);
```
   (WipeoutTraceInterest는 WipeoutTraceGlobalReflection보다 아래, 13-2장 섹션 다음에 두거나
   19장 섹션 안에 둬도 무방 — 순서보다 CorpseTraceInterest 옆에 두는 게 가독성상 낫다.)

2) PersonalMapKnowledge.cs — RegisterObject의 WipeoutTrace 분기 수정:
```csharp
if (tags.Any(t => t.Contains("WipeoutTrace")))
{
	_objectInterest[objectId] = WeightMath.WipeoutTraceInterest(causerStage);
}
else if (tags.Any(t => t.Contains("Corpse")))
{
	_objectInterest[objectId] = WeightMath.CorpseTraceInterest(causerStage);
}
```
