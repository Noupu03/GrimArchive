배치모드 구현현황 (2026-11-11)
══════════════════════════════════════════════════════════════════
작성 목적: `Assets/문서/공식문서/배치모드/`(설계명세서 v0.2 = 구현 대상, 핵심정리 v0.2 = 기획 의도·요약 참고, 순서도 2종은 코드화 대상 아님)의 구현 범위·구조·해석·미구현을 기록한다. 다시 손댈 때는 이 문서부터 확인한다(다른 구현현황 문서와 같은 관례).
사용자 확정(2026-11-11): ① 범위 = **핵심 + 기존 시스템 연동**(문 예약·코어 파괴 잠금·진화 후 저장 해제 포함, 시설 이동/철거/수리는 기존 `BuildingControlPanel` 그대로) ② **배치모드 안에서는 명세서 그대로 좌클릭 배치**(일반 화면의 "좌=선택/우=실행" 관례의 의도된 예외) ③ UI는 기존 규칙(OnGUI·`GUIMenuStyleUtil`·`GUIMouseUtil`·`BottomLeftPanelStack`·`GameInputScheme`·새 프리팹 없음)을 따른다.

■ 핵심 모델 (이걸 다시 손댈 때 먼저 볼 것)
──────────────────────────────────────────────────────────────────
저장·이동 명령·실제 도착은 서로 다른 시점이다(핵심정리 1장).
· **저장**(`DefenseRecord`): 유닛당 전역 하나(방·층·타일·방향·재지정 필요). 저장만으로 현재 작업·전투·이동을 끊지 않고 새 이동도 시작하지 않는다. 다른 방에 새로 저장하면 이전 방 지정을 교체한다.
· **이동 적용**(`IssuedMove` + `Unit.SetMoveCommand`): 누른 순간의 목적지·방향을 담는다. 그 뒤 저장 위치를 바꿔도 이미 발행한 명령은 안 바뀐다(1-4 표1). 실제 걷기는 시간을 재개해야 한다.
· **자동 복귀**: 단일 작업 종료 때만(1-6 표2). 최신 저장 위치를 따른다.
· **유입 인구는 따로 예약하지 않는다**: 이동 명령 자체가 예약이다 — `IncomingPopulation(room)` = 이동 명령을 받고 걷는 플레이어 몬스터 중 목적지 방이 현재 방과 다른 유닛의 인구수(생산 정원 검사 `BuildingManager.CountConfirmedIncomingPlayerPop`와 같은 기준). 취소·교체·도착이 곧 예약 해제라 "불러오기로 인구를 두 번 더하지 않는다" 류의 이중 계산이 구조적으로 안 생긴다.
· **대기 자리**(`_holds`): 이동 적용·자동 복귀로 선 자리에서는 `IdleFSMState`가 흩어지지 않고 정해진 방향으로 선다("명령에 담긴 위치·방향으로 대기"). 밀려났거나 다른 명령을 받으면 해제.

■ 입력 관례 (사용자 확정 — 일반 화면과 다름)
──────────────────────────────────────────────────────────────────
· 좌클릭: 유닛 선택(드래그 박스·Ctrl 추가)·빈 유효 타일에 순서 첫 유닛 배치·UI 버튼·회전 화살표 선택. 저장 위치의 유닛을 **두 번 클릭 = 미배치**. 회전 UI·명단 중 빈 곳 좌클릭은 배치·방향 확정이 아니다.
· 우클릭·ESC: 열린 회전 UI·인원 목록을 먼저 닫고 → 임시 선택 해제. **ESC만** 마지막에 모드를 나간다. 종료해도 저장한 위치·성공한 명령은 되돌리지 않는다.
· 시간: 진입 시 자동 일시정지, 종료해도 정지 유지(진입 전 배속으로 복구하지 않음). 모드 중 Space/1~4는 받지 않는다. 하단 [설치](건설)를 눌러도 모드가 유지되고 건설 확정은 기존대로 우클릭(시공은 시간 재개 뒤).

· R: 시계 방향으로 45도(8방향 전부 닿음) — 유닛을 놓는 중이면 다음에 놓을 방향(`PendingFacing`)을, 이미 놓은 유닛을 골랐으면 그 유닛들의 방향을 돌린다(회전 화살표가 열려 있으면 그 버튼으로 고른다). 놓는 중에는 커서 아래에 "방향 ○○ · R: 시계 방향 회전"이 뜬다. 명세에 회전 키가 없어 건설 미리보기의 R과 맞춘 사용자 요청이다(2026-11-13).

■ 장별 구현 현황 (✅구현 / 🔶부분·근사 / ❌미구현)
──────────────────────────────────────────────────────────────────
1-1 시간·화면   ✅ 진입 자동 일시정지·종료 후 유지·건설 미리보기에서 전환 시 미확정 미리보기만 닫음·[건설] 후에도 모드 유지·우클릭/ESC 단계 닫기. ✅ **이동 경로선 숨김**(2026-11-12 감사에서 어긋남을 발견해 같은 날 수정) — 예전엔 배치모드에 들어오기 전에 일반 화면에서 선택해 둔 유닛(`InputManager.selectedUnits`)의 명령 경로선·목적지·마우스 호버 마커를 `UnitGenerate.RefreshSelectionVisual`이 모드와 무관하게 그렸다. 지금은 `InputManager.IsPlacementModeActive`이면 그 유닛들의 경로 시각화를 끈다(선택 링과 단일 선택 시야선은 문서가 정하지 않아 그대로). 컴파일만 확인, 플레이 미확인. ✅ 표1: 미배치 카드(하단)·방 위 [이동 적용][유닛]·"방어 배치 N/M"+"현 인원"·전체 이동 적용·재지정 필요 표시·범위 ON/OFF·배치 순서 칸. 🔶 "오른쪽 미니맵 위" — 프로젝트에 미니맵이 없어 우하단 열(범위 ON/OFF 맨 아래, 그 위 순서 칸)에 쌓았다. 🔶 "관리 가능한 시설 색·반투명 처리": 2026-11-12에 **시설(청록)과 플레이어가 열고 닫을 수 있는 문(주황) 윤곽·옅은 채움**을 추가했다(`PlacementWorldView.DrawManageableOutlines`, 안개로 가려진 방 제외, 문은 담당 코어 가동 층만). ❌ 기본 벽·보스방 계단의 반투명 처리와 "유닛 선택 시 살짝 뜬 표현"은 문서가 최종 시안으로 대체 가능한 임시 표현이라고 한 부분이라 하지 않았다(대상 유닛은 맵 위 강조 테두리로 구분).
1-2 저장·미배치 ✅ 유닛당 전역 1개·방 교체·저장은 작업 비중단·[회전]/[미배치]/[이동 적용]은 대상 없으면 비활성·화살표 8개(45도)·미배치 3가지: [미배치] 버튼·두 번 클릭·**하단 카드 영역으로 끌기**(2026-11-12 추가 — 저장 위치의 유닛에서 시작한 드래그를 하단 가로 띠(`PlacementModeUI.UnplaceZoneRect`, 카드가 없어도 같은 자리)에서 놓으면 그 유닛만 저장 위치·방향 해제, 다른 곳에서 놓으면 기존 박스 선택, 드래그 중 영역이 "여기로 끌어 놓으면 미배치"로 표시됨). 영역 위치 계산은 `DefensePlacementTests`가 고정하고 실제 마우스 드래그는 플레이 미확인.
1-3 이동 적용   ✅ 대상 묶음은 저장 방 기준(방별·층 전체·목록 한 명·다중 선택)·유닛별 검사(생존·아군·진화 연출 중 제외·현재 방과 저장 목적 방 코어 권한·정원·몸체 지형·문 폭(`CanEntityEnterRoom`)·방 도달성(`CanFactionReachRoom`))·통과한 유닛만 작업 해제(`NotifyWorkerCommandChanged` — 진행도·지불 보존, 운반 중 분해 오브젝트 내려놓기)·실패 유닛은 기존 행동 유지+사유. 🔶 경로·문 폭은 방 단위 도달성+게이트 폭 근사(실제 A* 구조 경로 조회는 인류 전용 `RetreatBlockResolver`만 있다). ❌ **다른 층에 있는 유닛은 `WrongFloor`로 거부한다**(`CheckApply`) — 1-3장 "다른 층에서 작업하던 유닛도 해당 방·층의 저장 인원이면 검사 대상에 포함"과 3장 사례 2("다른 층에서 작업 중인 유닛이 저장 방으로 이동")는 층 이동이 가능해야 성립하는데, 플레이어 몬스터의 층 이동 수단이 없어 구조적으로 충족할 수 없다(목록에는 포함되고 이동 적용만 실패 사유 표시). ❌ 침공·디펜스 시작 시 자동 진형 강제는 하지 않음(문서 그대로).
1-4 재편집      ✅ 이동 적용은 눌렀을 때의 목적지·방향 보관·이후 저장 변경이 기존 명령을 안 바꿈·반복 적용은 교체(중복 예약 없음)·A 도착 후 B 자동 재이동 없음·직접 이동은 미배치로 돌려도 유지/자동 복귀는 복귀만 해제·건설 청사진이 발행된 이동의 최종 몸체와 겹치면 그 이동만 취소(0.5초 점검)·저장 위치가 겹치면 위치 유지+재지정 표시+이동 적용 건너뜀·취소된 이동은 복원하지 않음.
1-5 정원·유효성 ✅ 방어 배치 합산(같은 방 자기 위치 변경은 기존 몫 제외)·초과 시 이전 위치 유지·소속은 도착 때 바뀜·유입 표시("현 인원 4/6 (이 방으로 이동 중: 인구 2)", 유입 0이면 괄호 숨김 — 일반 화면 방 라벨에도 적용)·표1: 일부 성공·정원 부족 시 ETA 짧은 순 수용·정원이 생겨도 자동 재시도 없음·몸 크기/문 폭·건설 예약 겹침 사유 분리. 🔶 "저장 타일에 아군 일시 점유 → 인접 대기·비켜주기"는 기존 이동 시스템의 대체 칸 재지정에 맡김. ✅ **진화 추가 확보분을 실제 유입 검사에 포함**(2026-11-12 — 예전엔 "조회 API가 없다"며 뺐지만 `Unit.activeEvolutionSession.Definition.PostEvolutionPopulationCost`로 알 수 있었다): 이 방에서 진화 연출 중인 유닛의 (진화 후 인구 − 현재 인구)를 `DefensePlacementSystem.CommittedInflow`가 이동 중 유입에 더해, 이동 적용·자동 복귀의 남은 정원 계산에서 뺀다(`DefensePlacementMath.EvolutionExtraPopulation`, 줄어드는 진화는 0). 방 라벨의 "이 방으로 이동 중" 숫자에는 넣지 않는다(이동 유입이 아니므로). 이 방 밖에서 정원을 쓰는 다른 시스템(유닛 생산 등)의 정원 검사는 건드리지 않았다.
1-6 자동 복귀   ✅ 단일 작업 종료(건설·업그레이드·수리·철거·연구 대기열 소진) 뒤 최신 저장 위치로 복귀·반복 자원 작업은 복귀 없음·이동 적용 완료는 명령 위치·방향으로 대기·미배치는 대기. 🔶 직접 이동 중 전투: 기존 플레이어 이동 명령 FSM(우선순위 200 고착 — 전투·경계가 명령을 가로채지 않고 회피/점멸 반응만)을 근사로 사용 — "방어 뒤 같은 목적지로 계속"이 사실상 성립. ✅ **코어 수복·분해 이동(운반·재설치)·시체 정제 운반의 종료 훅 연결**(2026-11-12): `CoreSystem.CompleteCoreRestoration`(수복 작업자)·`BuildingManager`의 재설치 완료와 정제 입고 완료가 `DefensePlacementSystem.OnWorkTaskEnded`를 부른다. 명세 1-6 표2가 "단일 작업 종료"로 묶은 범주를 이 세 가지까지 넓힌 해석이다 — 수복만으로 취소됐던 이동이 되살아나지는 않는다(1-11). ❌ 연속 건설 큐는 프로젝트에 개념이 없다. ✅ **자동 복귀 중 전투 참여 + 전투 후 10초 경계 뒤 복귀 재개**(2026-11-12, 표1 "작업 종료 뒤 자동 방어 복귀"): 자동 복귀도 수동 이동 명령을 쓰되 `Unit.isDefenseAutoReturn` 표식으로 구분해 `UnitFSM`의 강제 고착(`Unit.HasForcedPlayerMove`)에서 뺐다. 새 FSM 상태 `DefenseReturnFSMState`(Combat 100·Tactical 50 아래, Idle 20 위)가 남은 `playerMoveTarget`으로 복귀를 이어 가고(`PlayerCommandFSMState.ExecutePlayerMove` 재사용 — 점유 대기·막힘 포기 포함), 복귀 중 같은 방 적을 인지하면 Combat이, 전투가 끝나면 `CombatFSMState.OnExit`가 세팅한 전투 후 경계(`postCombatAlertSeconds`=10초, Tactical이 유지)가 끝난 뒤에 다시 복귀한다 — 별도 타이머·재발행 없음, 유입 인구 예약도 유지. 방 이탈 제한 우회는 복귀 상태가 걷는 동안만(`Unit.MayLeaveRoomNow` — RoomConfinedMovement·AIMovementHelper.LeavesConfinedRoom·ForceMove 3곳). 직접 [이동 적용]은 여전히 "지정 위치 이동 우선"으로 강제 고착. kill-switch `AIBehaviorConfig.defenseReturnYieldsToCombatEnabled`. 컴파일·순수 판정 테스트(`UnitCommandMathTests`)만 확인, **실행·헤드리스·플레이 미확인**.

· **검증 상태**: 리팩토링 뒤 `dotnet build` 오류 0·경고 71 확인. **Unity 배치 테스트는 리팩토링 뒤 재실행하지 못했다**(시스템 메모리 부족으로 중단) — 위의 1177/30은 리팩토링 전 수치이므로 메모리 여유가 생기면 다시 돌려 `DefensePlacementTests` 32건과 기준선(30 실패, 8개 픽스처)을 확인할 것.
