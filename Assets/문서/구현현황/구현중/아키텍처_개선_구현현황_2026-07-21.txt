GrimArchive 아키텍처 개선 (Phase 1~6) 구현 현황 — 2026-07-21
작성일: 2026-07-21

이 문서는 거대해진 GameSession과 Unit 클래스의 책임을 분리하고 유지보수성을 높이기 위한 아키텍처 개선 작업의 구현 현황을 기록합니다.
HAARE 프레임워크에 기반하여 Native Routine으로 구조를 변경하였고, OCP(개방-폐쇄 원칙)를 준수하도록 리팩토링되었습니다.

태그
  ✅ 완료       — 기능 분리 및 테스트 정상 작동 확인 완료
  ⚠️ 진행중     — 진행 중이거나 보완이 필요한 부분

---

✅ Phase 1: OffenseProcessor 순환 참조 제거
  - OffenseProcessor의 정적 싱글턴(Instance) 제거 완료.
  - VContainer DI (GameCompositionRoot)를 통한 주입으로 의존성 관리 변경.
  - 관련 UI(StatusInfoPanel, OffenseDebugWindow)에서 GameSession.Instance.OffenseProcessor를 참조하도록 수정 완료.

✅ Phase 2 & 3: GameSession 책임 분리
  - UnitRegistry, ObjectSpawner, PartyService, CombatEventService, DebugInputHandler 추출 완료.
  - GameSession 내의 코드가 대폭 감소하였으며, DI로 주입된 서비스 객체들을 활용하여 로직 수행.

✅ Phase 4: Unit 데이터 컴포넌트 분리
  - 거대한 Unit.cs 내부 필드를 4개의 구조체로 분리 완료:
    - UnitStatusEffects
    - UnitCombatState
    - UnitPerceptionState
    - UnitAIWeightState
  - 기존 코드의 호환성을 유지하기 위해 임시 래퍼 프로퍼티(get/set) 유지 (추후 직접 접근으로 단계적 마이그레이션 가능).

✅ Phase 5: CastRay 파이프라인 핸들러 분리
  - UnitFunction.CastRay 내부의 복잡한 로직을 IVisionTileHandler 인터페이스로 분리.
  - TerrainRevealHandler, ObjectPerceptionHandler, UnitPerceptionHandler 로 분할하여 OCP 준수.

✅ Phase 6: 마무리 검증 및 테스트
  - 전체 소스 코드 및 Editor 스크립트 컴파일 테스트 통과 (오류 0개).
  - 새로 분리한 스크립트들을 Assembly-CSharp.csproj 에 누락 없이 모두 추가 완료.
  - 관련 유닛 테스트(Assets/Tests) 빌드 오류 없음 확인.
