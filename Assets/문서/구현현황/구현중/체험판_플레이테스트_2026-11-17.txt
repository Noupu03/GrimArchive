체험판(1층 보스까지) 플레이테스트 안내 — 2026-11-17
==========================================================

목표
  스팀 체험판처럼 "처음 켠 사람이 1층 보스 처치 → 1층 코어 완전 활성화까지 막힘 없이 가는가"를 확인하고,
  막힘·혼란·지루함·버그를 찾아 고친다. 새 기능은 넣지 않고 있는 것을 다듬는다.

체험판 범위
  시작 : Kubonhon 씬 실행(게임 화면에서 바로 시작)
  끝   : 1층 보스 처치 → 코어방 클리어 → 코어 정보 패널에서 "완전 활성화"
  포함 : 첫 인류 웨이브 방어 / 다음 방 공략 / 시설 건설·유닛 생산 / 정규 웨이브 / 보스방
  범위 밖(만지지 않아도 됨) : 2층 이후, 연구 심화, debug 메뉴

1. 준비
----------------------------------------------------------
  - Unity에서 Assets/Scenes/Kubonhon.unity 를 열고 Play. (ssh 씬 복제본이라 내용은 같다.
    타이틀에서 시작하면 ssh로 가므로 로그가 남지 않는다 — 반드시 Kubonhon에서 바로 실행)
  - 기록은 화면 표시 없이 백그라운드로 남는다(2026-11-18: 상단 안내·F8/F9 단축키 제거).
  - 기록 위치 : <프로젝트 폴더>/PlaytestLogs/session_날짜_시간/log.txt
    (git에는 올라가지 않는다 — 필요한 세션 폴더만 공유)

----------------------------------------------------------
2. 테스터 규칙
----------------------------------------------------------
  - 첫 테스트는 설명 없이 플레이한다(체험판 사용자처럼). 옆에서 보는 사람은 도와주지 말고 관찰만.
  - "어떻게 하지?", "왜 안 되지?" 싶은 순간과 버그는 관찰자가 시각과 함께 메모한다(F8/F9 단축키는 제거됨).
  - 30분이 지나도 보스에 못 가면 거기서 멈춘다(그것도 결과다).
  - 끝나면 아래 3번 설문을 적고, log.txt와 함께 남긴다.

----------------------------------------------------------

  4) 인류 웨이브가 "생각하고 움직이는" 것처럼 보였나? (1~5) 기억나는 장면 :
  5) 지루했던 구간(기다리기만 한 시간 등) :
  6) 보스전 난이도 (너무 쉬움 1 ~ 5 너무 어려움) :

  8) 체험판이면 계속 해 보고 싶은가? (1~5) 이유 :

4. 관찰자 체크리스트 (구간별, 걸린 시간도 적기)
----------------------------------------------------------
  A. 시작 ~ 첫 웨이브
     [ ] 시작 유닛·자원·목표가 화면에서 이해되는가
     [ ] 웨이브 게이지/예고를 알아보는가
     [ ] 첫 웨이브에서 유닛 선택·이동·공격 명령을 스스로 하는가
  B. 다음 방 공략
     [ ] 공략할 방과 확보 조건(적대 0)을 아는가
     [ ] 문을 공격해서 지나가야 한다는 걸 아는가
     [ ] 방 확보 후 무엇이 해금됐는지 아는가
  C. 운영(건설·생산·시체)
     [ ] 설치 메뉴·작업자 배정을 찾는가 / 건설 불가 알림을 이해하는가
     [ ] 자원이 왜 늘고 줄었는지 아는가(처치 즉시 보상 없음 → 시체 정제)
     [ ] 유닛 생산 대기·출현을 이해하는가
  D. 정규 웨이브
     [ ] 웨이브 사이에 할 일이 있는가(멍하니 기다리는 시간)
     [ ] 아군이 이유 없이 멈추거나 왕복하지 않는가
  E. 보스방
     [ ] 보스방 위치를 찾는가
     [ ] 보스전이 공정하게 느껴지는가(위협 타일 예고를 보고 피하는가)
     [ ] 보스 처치 후 코어 활성화 방법을 스스로 찾는가
  공통
     [ ] 오류·멈춤·소프트락(진행 불가)
     [ ] UI 글자 잘림·겹침
     [ ] 프레임 저하

----------------------------------------------------------
5. 로그 읽는 법 (log.txt)
----------------------------------------------------------
  - "◆" = 진행 시점(웨이브 시작·종료, 방 확보, 보스 처치, 코어 활성화). 시점 간 간격 = 구간 소요 시간.
  - "입력 없음" = 게임이 진행 중인데 30초 동안 아무것도 안 함 → 할 일을 모르거나 지루한 구간 후보.
  - "알림" = 화면에 뜬 안내(이동 불가·건설 불가 사유 등). 맨 아래 요약의 "자주 뜬 알림"이 많으면 막힌 행동이다.
  - "오류" = 콘솔 Error/Exception. 하나라도 있으면 버그 후보.
  - 맨 아래 "세션 요약" = 총 시간, 시점 목록, 사망 수, 클릭 수, 표시 수.

----------------------------------------------------------
6. 발견점 정리 양식 (세션이 끝날 때마다 누적)
----------------------------------------------------------
  분류 : 막힘(진행 불가) > 혼란(방법을 모름) > 버그 > 지루함 > 연출
  | # | 분류 | 구간 | 내용 | 근거(로그 시각/스크린샷) | 재현 빈도(n/세션수) | 상태 |
  수정 우선순위는 막힘·혼란부터. 같은 문제가 2명 이상에게서 나오면 바로 수정 대상.

기술 메모
----------------------------------------------------------
  - 기록기 : Assets/Script/Playtest/PlaytestSessionLogger.cs — 씬 이름이 "Kubonhon"일 때만 자동 생성(씬 수정 없음).
    게임 상태는 읽기만 한다. 알림 기록용으로 NoticeCenter에 정적 이벤트 OnNoticePushed를 추가했다(동작 영향 없음).
  - 판정 : 1층 보스 처치 = 보스 유닛(unitType.isBoss)이 살아 있는 걸 본 뒤 사라짐 / 코어 활성화 = 1층 코어 CoreEverActivated.
  - Kubonhon 씬은 빌드 설정에 넣지 않았다. 실제 체험판 빌드 때는 타이틀이 불러오는 씬 이름(TitlePresenter·GameExitFlow의
    "ssh")과 함께 정할 것.
  - 확인 상태 : 컴파일 오류 0만 확인. Unity에서 실제 실행(씬 열림·기록 생성)은 아직 확인하지 않았다.
