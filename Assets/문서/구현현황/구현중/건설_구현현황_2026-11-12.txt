■ 문서가 뒤집은 것 (기존 구현과 달라진 점 — 이미 반영)
────────────────────────────────────────────────────────────────────────
· 손상 시설: 예전 `CurrentHp < MaxHp`면 가동 정지 → 이제 **손상 효율 e = 0.5 + 0.5×HP비율**로 계속 가동하고, 실제 수리·강화·철거·분해 작업이 진행되는 동안에만 멈춘다(`BuildingData.IsOperational`/`FieldWorkActive`/`DamageEfficiency`).
· 작업자 피격: 예전 배정 해제·자동 재개 없음 → 이제 **배정·진행·지불·목적지 보존**, 전투 참여, 전투 종료 후 10초 경계 뒤 자동 재개. 같은 작업 재지시는 "작업 우선"(그 일이 끝날 때까지 자동 공격·추격·능동 방어 정지).
· 신규 건설 완료: 예전 HP 비율 승계 → 이제 **완성 시설 최대 HP로 전부 회복**(강화는 여전히 비율 승계). 착공 시 시공체는 건설 단계 최대 HP로 생성.
· 코어 파괴 중: 예전 건설·수리·강화·철거 차단 → 이제 **확보한 방에서 가능**, 생산·자원·연구·정제만 정지. **새 생산 예약·연구 선택도 가능**(전액 선점, 실제 생산은 수복 뒤 가동 조건 재검사) — `BuildingData.CanTakeReservations`.
· 시설 이동: 이동용 분해·운반·재설치 **무상**(예전 분해비 60), 분해 도중 시설 피격은 취소가 아니라 **작업·지불 보존**, 운반 중 직접 피격은 분해물 낙하 후 전투·경계 뒤 **자동 회수**, 저장·정제 시설은 **비우지 않고 이동**.
· 수리→강화 교체: 수리 환급분을 포함해 강화 비용이 충족되면 수리를 취소 정산하고 교체, 부족하면 수리 유지.
· 내부 작업자: 예전엔 시설 둘레에 서서 일했다 → 이제 **시설 안으로 들어가 모습이 사라진다**(격자·시야·타깃팅·행동에서 빠짐). 건설·수리·강화 작업자(외부 역할)와 내부 작업자(내부 역할)는 서로 다른 역할이다.

■ 구조 (이걸 다시 손댈 때 먼저 볼 것)

Assets/Script/Building/ConstructionRules.cs (신규, 순수 함수) — 손상 계수 `DamageCoefficient`/`ApplyToCombatDamage`, 화면 HP `DisplayHp`, 건설 단계 HP `ConstructionStageMaxHp`(자리표시자 10%), 재설치·최대 HP 변경 환산(`ReinstallStartHp`/`ReinstallCompleteHp`/`HpAfterMaxChange`), `IsFieldWorkStoppingFacility`, `ShouldResumeAssignedWork`, `ReleasedAfterStart`.
BuildingManager.cs
  · `UpdateProcess`: 현장 작업 시설도 가동 틱을 이어서 돈다(예전엔 `continue`로 건너뜀). **현장 작업자(시설 둘레, `GatherActiveAdjacentWorkers`)와 내부 작업자(시설 안, `GatherInsideWorkers`)는 입력 버퍼가 따로다** — 수리·강화가 실제로 진행되지 않는 동안 안에 있는 내부 작업자는 계속 가동에 기여한다. 손상 효율 `dmgE`를 엔진 속도/산출 인자로 넘긴다.
  · `TickBuildingFieldTask`: 케이스별 `FieldWorkActive` 갱신(강화=착공+작업자, 수리=`IsFieldWorkStoppingFacility`, 철거=작업자, 분해=작업자), 현장 작업의 코어 게이트는 항상 통과(`coreActive = true`). 철거·분해는 안에 살아 있는 내부 작업자가 나올 때까지 착수하지 않는다(`BlockUntilInsideWorkersExit`, 대기 사유 "내부 작업자 퇴장 대기").
  · **작업 이동 = 기존 자동 방어 복귀 장치 재사용**: `IssueInternalEconomyMove`가 `isDefenseAutoReturn=true`(전투·경계에 밀리고 끝난 뒤 이어지는 자동 이동, `DefenseReturnFSMState`가 걷는다)로 발행한다. 재지시(작업 우선)는 `markHalt:true` 고착 이동 + `Unit.workPriorityActive`. 같은 스위치 `AIBehaviorConfig.defenseReturnYieldsToCombatEnabled`를 따른다(꺼지면 예전 고착 이동).
  · `TickWorkerResume`(0.5초): 배정은 있는데 작업 자리에 없고 전투/경계 상태가 아니며 다른 이동·운반이 없으면 작업 자리로 재발행(`ConstructionRules.ShouldResumeAssignedWork`). 안에 있는 유닛과 비켜 준 직후(`Unit.workResumeHoldUntil`)는 건너뛰고, 문 확장 작업자는 `ResumeDoorWorker`가 맡는다.
  · `NotifyUnitHit`: 배정을 풀지 않는다. 시체·분해물 운반 중 직접 피격이면 내려놓고(`DropCorpseToField`/`DropDismantledBuildingPackage`가 이제 오브젝트를 반환) 해당 오브젝트를 다시 줍는 자동 이동을 발행(입고 예약·목적지 유지). 작업 우선 중이면 낙하하지 않는다.
  · `TryAssignWorkerToBuilding`: 같은 건물·같은 역할 재배정 = 작업 우선. 배정 역할은 시설의 현재 모드로 정한다(현장 작업이 없는 생명 에너지·연구 시설 = 내부 역할, 그 밖 = 외부 역할). `NotifyWorkerCommandChanged`는 배정·문 확장 배정을 풀고 안에 있던 유닛은 나오게 한다.
  · `TryStartFacilityUpgrade`: 수리 중이면 환급 포함 비용 검사 후 교체.
  · 정제시설 분해 착수(`IsRefineryBeingDismantled`)부터 새 반입 후보에서 제외.
Production 엔진: `LifeEnergyCycleTracker.Advance(..., damageCoefficient)`(속도 e + 구간별 기여로 한 주기 산출 `1 + 보정 + WeightedEfficiencyDelta`, 스냅샷 포함), `CorpseRefineryState.TickAutoRefine(..., outputMultiplier)`, 연구·생산은 기존 속도 배율 인자에 e 전달, `ConstructionOrUpgradeSession` 신규 건설 완료 HP.
Unit.cs: `workPriorityActive`, `workQueue`, 내부 작업 상태(`assignedWorkIsInternal`·`insideFacility`·`insideEntryTile`·`insideExitRequested`/`insideExitCause`·`internalCombatSetting`·`workResumeHoldUntil`), 문 확장 배정(`assignedDoorExpansion`·`doorExpansionEnd`).

· 퇴장 원인과 처리(`InternalWorkRules.ExitCause`): 담당 코어 파괴(배정 유지, 수복 뒤 자격 재검사 후 재입장) / 전투 대응(같은 방에 적대 유닛이 있거나 시설이 2초 안에 피격 — '대응' 설정만, 작업 우선 중엔 대응 안 함, 배정 유지) / 분해 착수(배정 유지, 원래 자리 밖에서 대기) / 철거 착수(배정 해제 후 방어 위치 복귀) / 배정 해제·직접 명령(나온 뒤 새 명령). 수리·강화가 실제로 진행돼도 안에 있던 인원은 나오지 않고 안에서 대기한다(가동만 멈춘다).
· 퇴장 자리: 몸 전체가 들어가는 상하좌우 인접 빈 공간(입장 지점 우선). 나갈 유닛을 먼저 처리한 뒤 들어올 유닛을 본다. 빈 공간이 없으면 순간이동·자리 교환 없이 퇴장 대기(`RequestExitYield`): 출구를 막은 아군 중 작업·전투·운반·이동 중인 유닛은 강제로 취소하지 않고, 대기 중인 아군은 시설 둘레에서 벗어난 빈 칸으로 비켜 주며(`StepAsideFor` — 비켜 준 작업자는 2.5초간 자리로 돌아오지 않음), 퇴장 대기 중이면 둘레에 선 다른 대기 아군에게도 같은 비켜주기를 적용한다. 분류 표는 `InternalWorkRules.ClassifyBlocker`/`ResolveYield`.
· 내부 사망: 시체는 몸 전체가 들어갈 빈 인접 공간으로 배출(`ResolveInsideDeath` → `GameSession.RemoveDeadUnit`이 그 자리에 시체 생성), 공간이 없으면 배출 대기(`BuildingData.PendingInsideCorpses` — 정식 보관물이 아니라 부패 계속, 0.5초마다 재시도). 분해·철거가 끝나면 미배출 시체는 원래 시설 자리에 남고(필요하면 겹침), 시설이 파괴되면 소멸한다. 시설 파괴·철거로 격자에서 빠지면 안에 남은 생존 유닛은 해제된 시설 영역에 겹치지 않게 나온다(`EjectInsideWorkersAtFootprint`).
· UI: 작업자 목록 행에 내부 작업자의 [전투 대응/무시] 토글, 행 활동에 "시설 안/퇴장 대기/입장 대기: 사유", 시설 패널에 "내부 작업자 N/정원", 작업 현황에 "(시설 내부)" 행(한 주기 진행·시설 안 인원·대기 사유), 배치모드 인원 목록에 "시설 안에서 작업 중" 비고.

· 내부 작업 동작 값(문서에 없어 정한 것): 입장·퇴장 틱 0.25초, 시설 피격을 전투로 보는 시간 2초(`FacilityHitMemorySeconds`), 비켜 준 작업자가 돌아오기 전 대기 2.5초(`YieldHoldSeconds`), 비켜 달라는 요청 간격 1초, 비켜 줄 때 시설 둘레에서 1칸 이상 떨어진 빈 칸, 배출 대기 시체 재시도 0.5초.
· "현재 방의 전투 인지" 근사: 시설이 있는 방에 그 유닛에게 적대적인 살아 있는 유닛(시설 안이 아닌)이 있으면 전투 인지로 본다. 밖으로 나온 뒤엔 일반 시야·인지 규칙을 따른다.
· 작업 우선은 "정지(`isHalted`) + `workPriorityActive`"로 구현(문서에 방법이 없는 해석). 작업 이동은 기존 자동 방어 복귀 장치(`isDefenseAutoReturn` + `DefenseReturnFSMState`)를 재사용하며 상태 라벨은 "작업 이동"으로 구분한다.

■ 알려진 변경·해석
────────────────────────────────────────────────────────────────────────
· 건설·수리·강화를 끝낸 작업자는 이제 항상 배정이 풀리고 방어 위치로 복귀한다 — 생명 에너지·연구 시설을 지은 작업자가 그대로 그 시설의 작업자로 남던 예전 동작은 건설 명세 1-2-1(건설 작업자와 내부 작업자의 분리)에 맞춰 바꿨다. 시설 가동에 작업자가 필요하면 목록에서 다시 지정한다.
· 연구시설 내부 정원 자리표시자가 2라서 예전(최대 4명)보다 줄었다.
· 내부 작업자는 시설 안에 들어가면 화면에서 사라지고 선택할 수 없다 — 시설 UI의 작업자 목록으로 해제·설정을 다룬다.
· 시작방 생산시설은 정면 구역이 빈 방향으로 놓이고 아무 방향도 안 되면 예전 시설 둘레 출현으로 폴백한다. 건설 미리보기에서 R로 회전한다.
· 이동 UI는 이전의 "가까운 빈 곳 자동 선택"을 목적지·방향 직접 지정(우클릭)으로 바꿨다. 제자리 회전은 [회전] 버튼.
· 코어가 파괴된 층에서도 생산 예약·연구 선택이 가능해졌다(예전엔 막힘, 엔진의 `ProductionEnqueueBlock.CoreInactive`는 남아 있고 UI가 `isCoreValid: true`로 호출한다).
