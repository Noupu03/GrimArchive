■ 1. 몬스터 배치 프리셋 시스템
════════════════════════════════════════════════════════════════════════

[설계 변천사 — 왜 코드에 "재구현"/"재수정" 주석이 많은지]
1차 설계(지시서 원문 그대로): 몬스터 선택 → R키로 개별 소집 토글 → 우클릭 이동 → R키로 소집 해제 시
그 위치를 저장. 끝까지 구현했다가, 사용자가 "일단 소집 관련된 모든 과정들을 롤백해봐"라고 요청해
Unit.isMustered/defenseStartPosition 필드, NavigationFSMState 소집 대기 분기, UnitFSM 자동 해제
로직, GameSession.ApplyMonsterDefenseStartPositions, InputManager의 R키/우클릭 훅을 전부 원상
복구했다(이 시점 커밋 없음 — 대화 내에서만 존재했다 사라짐).

2차 설계(현재 구현, 완전히 다른 UX): "R키 → 방 단위 배치 모드 진입(시간 정지) → 점령한 방 선택 →
몬스터 선택/타일 선택 두 서브모드를 오가며 방 안 타일에 유닛을 하나씩 배치 → R키로 모드 종료(시간
재개, 유닛 행동에는 영향 없음) → 0층에 인류가 소환되는 시점에 실제로 그 위치로 이동 + 소집 대기 →
전투 인지 시 소집 해제." 아래 표는 이 2차 설계 기준이다.

[핵심 데이터/트리거]
  - Unit.cs: defenseStartPosition(Vector2Int?, 디펜스 시작 위치), isMustered(bool, 소집 대기 플래그).
  - GameSession.ApplyMonsterDefenseStartPositions() — "0층 인류 소환" 트리거 시점에 호출.
    호출부 2곳(둘 다 HumanWaveManager.cs): PreSpawnWaveUnits()(사전 스폰 경로, 일반적인 경우) /
    StartWave()의 즉시 스폰 폴백 분기(사전 스폰이 스킵된 예외 경로) — 정확히 한쪽만 실행되도록
    조건부로 나뉘어 있어 중복 호출 없음.
  - UnitFSM.SelectState() — Combat/Tactical 진입을 감지해 isMustered를 자동 해제.
  - NavigationFSMState — isMustered면 자유탐색 대신 제자리 대기(HoldPosition).

[구현 현황 — 지시서 항목별]
✅ R키 배치 모드 진입/종료 — InputManager.ToggleMonsterPlacementMode. 웨이브 대기 중(WaveState.Idle)
   에만 진입 가능(웨이브 진행 중엔 경고 로그 후 거부). 진입 시 Time.timeScale=0.0001f로 시간 정지
   (스페이스바 일시정지와 동일 메커니즘, 기존 일시정지 상태를 기억했다가 종료 시 복원).
✅ 점령한 방 선택 — InputManager.UpdateMonsterPlacementMode Phase 1. roomGrid 조회 +
   RoomFaction==Player인 방만 선택 가능. 방을 클릭하면 SelectPlacementRoom이 그 방으로 고정.
✅ 몬스터 선택 / 타일 선택 서브모드 전환 — 패널의 두 버튼(DrawMonsterPlacementUI). 몬스터 선택은
   기존 좌클릭/드래그박스/더블클릭 선택 로직(UpdateSelectionDragAndClick)을 그대로 재사용.
✅ 타일 선택 전환 시 대기열 구성 — EnterTileSelectSubMode가 선택된 유닛 중 플레이어 몬스터만
   골라 _placementQueue에 추가(중복 방지). "몬스터 선택 → 타일 선택"을 여러 번 오가며 추가 선택분을
   누적할 수 있음.
✅ 타일 클릭/드래그로 순서대로 배치 — TryPlaceQueuedUnitAt. 대기열 맨 앞부터 소비, 드래그 중 같은
   칸 중복 소비 방지(_placementHasLastPaintedTile).
✅ 배치 취소(재클릭) — 이미 배치된 타일을 다시 클릭하면 FindUnitPlacedAt으로 찾아 취소하고 대기열
   맨 앞으로 되돌린다(즉시 재배치 가능).
✅ 벽/건물 타일 배치 차단 — CreateMap.IsStaticTileWalkable(UnitFunction.CanMove와 동일 기준,
   Tile.isStructureExist로 벽·건물 통일 판정) 검사 추가.
✅ 방 밖 몬스터 선택 차단 — IsUnitSelectableInPlacementMode. 몬스터 선택 서브모드에서 선택된 방
   밖 유닛은 클릭해도 완전히 무시(선택도 공격도 안 함).
✅ 방 안 몬스터 강조 — 사용자 요청 "강조 방식은 자유롭게" → 방 색상을 건드리는 대신, 방 밖 유닛의
   SpriteRenderer 알파를 낮춰(DimUnitsMatching, PlacementDimUnitAlphaFactor=0.2) 상대적으로 강조.
   타일 선택 서브모드에서는 전부 흐리게(격자/타일 강조). RefreshPlacementUnitDim이 서브모드 전환마다
   재계산.
✅ 다른 방으로 이동 시 배치 취소 — UnitFunction.SyncRoomAffiliation에 추가. "정착"(=지금 플레이어
   이동 명령 수행 중이 아님)한 방이 배치 지정 방과 다르면 defenseStartPosition을 null로. 배치 위치로
   가는 도중 거치는 방/복도에서는 오검출 안 되도록 이동 명령 진행 중엔 검사를 건너뛴다.
✅ 배치된 몬스터 실루엣 표시 — DrawPlacementSilhouettes. 최초엔 고정 픽셀 크기라 카메라 줌에 따라
   비율이 이상해지는 버그가 있었음 → WorldRectToGUIRect로 월드 좌표 두 점을 각각 투영하는 방식으로
   교체, 카메라 배율과 무관하게 항상 실제 타일 크기로 보임.
✅ 타일 선택 시 격자 강조 — DrawTileSelectGrid + DrawWorldLineOnGUI(축 정렬 전제, 카메라 회전 없음).
✅ 방 강조 표시 방식 — 최초엔 ChangeRoomColor로 방 전체를 어둡게/밝게 칠했으나, 사용자가 "색상은
   이미 점령 여부에서 사용하고 있잖아, 다른 방법으로 하자"고 정정 → 방 타일 색은 전혀 건드리지 않고
   화면 테두리 선(DrawEligibleRoomBorders/DrawSelectedRoomBorder)으로만 강조하도록 전면 교체.
   IMapColorizer.GetRoomColor/MapRandering.GetRoomColor(중간 단계에서 스냅샷 복원용으로 추가했던 것)도
   더 이상 안 써서 되돌림.
✅ 배치 모드 UI가 기존 UI와 안 겹침 — DebugInfoPanel/StatusInfoPanel이 오른쪽 상단 y10~510을 이미
   차지하고 있어, 배치 패널을 PlacementPanelTopY=530 고정으로 그 아래에 배치.
✅ "0층 인류 소환" 시 실제 이동 + 소집 — ApplyMonsterDefenseStartPositions. defenseStartPosition이
   있으면 playerMoveTarget/isManualMoveCommand로 이동 명령(우클릭 이동과 동일 경로 재사용) +
   isMustered=true.
✅ 미배치 몬스터도 제자리 소집 — 사용자 요청으로 추가. defenseStartPosition이 없는 플레이어 몬스터도
   이동 없이 그 자리에서 isMustered=true(같은 함수의 else 분기).
✅ 소집 도착 후 바라보는 방향 — GameSession.ApplyDefenseFacingDirection. 시작방이면 이 층으로
   올라오는 계단 방향(TryGetStairApproachPosition, 실패 시 TryGetStairPosition), 그 외 방이면
   시작방까지 BFS 최단 경로상 첫 번째 문(TryGetDefenseFacingDoorTile) — 최초엔 "시작방=자신의 아무
   문"으로 잘못 구현했다가 사용자가 "시작방은 계단 방향" "다른 방은 시작방으로 향하는 문"으로 정정.
   배치 이동 도착 시(PlayerCommandFSMState.CompletePlayerCommand)와 제자리 소집 시
   (ApplyMonsterDefenseStartPositions) 양쪽에서 호출.
✅ 소집 상태 라벨("소집") — UnitFSM.GetLabel이 isMustered면 현재 FSM 상태와 무관하게 항상 "소집"
   반환(이동 중이든 도착 후 대기 중이든 동일 표시).
✅ 소집 해제 = 전투 인지 시점 — UnitFSM.SelectState. 최초엔 next가 TacticalFSMState이기만 하면
   무조건 해제했는데, 이게 버그였다(아래 "발견한 버그" 참고) → 실제 전투 인지(Combat 진입 / 직접
   목격 personalSpottedEnemies>0 / 전투 종료 후 뒷정리가 아닌 경계·수색)만 정확히 골라 해제하도록 수정.

[사용자가 확인/정정해준 판단]
  - "즉시 이동하는게 아닌, 웨이브 시작 시 해당 위치로 이동" — 배치 모드 중 클릭은 데이터만 저장,
    이동은 0층 인류 소환 시점에만.
  - "전투 시작 시점 인지 후부터 자유롭게" — 소집 해제 조건을 "전투/전술 상태 전체"에서 "실제 전투
    인지"로 좁힘(아래 버그 참고).
  - "방선택을 색상 변경 말고 다른 방법으로" — 방 강조를 색칠→테두리로 전면 교체.
  - "강조 방식은 자유롭게" — 유닛 알파 흐림으로 구현(사용자 재량권 위임 받음).
  - "미배치 몬스터도 제자리 소집" — 배치 여부와 무관하게 전 플레이어 몬스터가 소집 대상.

[알려진 제약 / 스텁]
  - 타일 배치 시 벽/건물만 막고, 다른 유닛이 현재 서 있는 칸인지는 확인하지 않는다(정적 지형 기준
    IsStaticTileWalkable만 검사) — 실제 배치 시점에 그 자리에 누가 서 있어도 배치 자체는 허용됨.
  - 방에 문(게이트)이 여러 개일 때 "시작방의 문"은 첫 번째로 찾은 게이트를 그대로 쓴다(가장 가까운
    문 선택 로직 없음) — 시작방에 문이 여러 개인 맵 구조가 실제로 있다면 추가 보정 필요.
  - 배치 대기열 UI는 텍스트 목록("근접 탱커 X6")만 지원, 스프라이트 아이콘 나열 옵션은 미적용.

✅ 시간에 따른 진행 — HumanWaveManager.cooldownTimer/waveCooldown 정규화(진행도 0=출발, 1=도착).

✅ 파티 위치와 게이지 진행도 동기화.
✅ 도착 임박 시 게이지 점멸 — ImminentThresholdProgress=0.85 이상일 때 사인파 알파(자리표시자 값,
   실제 임계값/속도는 지시서가 "플레이 테스트 후 조정"으로 명시 위임).
✅ 던전 도착 시점 판정 — WaveState.Idle이 아니게 되는 순간(=StartWave 발동) progress=1로 고정.
   도착 이후 UI 제거/전환 방식은 지시서가 "후속 구현에서 결정"으로 명시 위임했으므로 미구현(만땅 유지).

[UI 표현 반복 수정 이력]

    먼저 배경으로 깔고 트랙을 그 위에 진행도 비율만큼 그리는 최종 방식(현재 코드).
  - "notice ui 조금 아래로" 요청으로 NoticeCenter.TopMargin을 웨이브 게이지 하단(y~42) 아래인 60으로
    내림 — 두 UI가 겹치던 문제.

■ 3. Notice 시스템 (NoticeCenter) — rythoom 프로젝트 이식

   QuestCompleteColor/WarningColor 3색, 화면 상단 중앙에 위→아래로 쌓이고 각자 독립적으로 만료.
✅ 지속형(상태 기반) 알림 — PushPersistent(key, text, color?)/Remove(key). 같은 key로 다시 부르면
   기존 걸 지우고 새로 넣어 교체(자동 만료 없음, Remove 호출 시에만 사라짐). 배치 모드의 3단계 안내

   key="MonsterPlacementMode".
✅ 웨이브 시작 임박 알림 — UIManager.CheckWaveStartNotice. 기존엔 매 프레임 조건부로 직접 OnGUI
   그리던 배너를 "3초 이하로 떨어지는 순간(엣지)에 1회 Push"로 교체.
✅ 일시정지 무시 — Time.unscaledDeltaTime으로 카운트다운(최초엔 Time.deltaTime을 써서, 배치 모드
   진입 자체가 시간을 멈추다 보니 진입 안내 알림이 거의 안 사라지는 문제가 있었음 → 수정).
✅ 기존 UI와 겹침 방지 — TopMargin=60(웨이브 게이지 아래).

   한 번 갱신되지만, 제자리 소집(위치 불변)은 이 갭이 그대로 드러났다. 수정: 값을 바꾼 직후

■ 검증 상태 — 실제로 켜서 확인이 필요한 항목
════════════════════════════════════════════════════════════════════════
오늘 작업은 전부 코드 리뷰/논리 검증 수준(브레이스·괄호 밸런스 확인, 호출부 추적)으로만 확인했고,
Unity 에디터에서의 실제 플레이 검증은 진행하지 못했다(코드 작성 환경에 Unity 실행 불가). 데모 전
반드시 확인할 것:
  1. 배치 모드 전체 플로우(R키 진입 → 방 선택 → 몬스터 선택 → 타일 선택 → 배치 → R키 종료)가
     실제로 끊김 없이 동작하는지.
  2. 0층 인류 소환 시 배치된/미배치 몬스터 둘 다 정상적으로 소집 대기 상태가 되는지, 방향이 맞는지,
     "소집" 라벨이 뜨는지(오늘 마지막으로 고친 두 버그 — 실제로 화면에서 확인 안 함).
  3. 전투 발생 시 소집이 정상적으로 풀리는지(특히 이전 웨이브에서 싸운 적 있는 몬스터).
  4. 웨이브 게이지가 실제 화면에서 웨이브 시작~도착까지 자연스럽게 채워지는지, 임박 점멸이 눈에
     띄는지.
  5. Notice 알림(배치 모드 3단계 안내, 웨이브 임박 경고)이 실제로 뜨고 사라지는지, 다른 UI와 겹치지
     않는지.
  6. 방 테두리 강조(초록=선택 가능, 금색=선택됨)가 실제로 잘 보이는지 — 밝기/두께 값은 전부 첫
     시도 값이라 조정이 필요할 수 있음.

     형태를 유지한 채 전진. 같은 랭크에 유닛이 여럿이면 AddRank/LaneOffset이 rowY 기준 좌우(Y축)로

     인원에서 항상 -Y(아래) 쪽에 한 명 더 치우쳤다. 홀수는 중앙 포함 대칭(-1,0,1), 짝수는 중앙을
     비우고 좌우 동수 대칭(-2,-1,+1,+2)이 되는 LaneOffset(i,n)으로 교체.
   - 버그 2(같은 신고, 재확인 후 발견): 레인은 고쳤는데도 기준선 rowY 자체가 안 맞았다. 원인은

     좌상단(TryGetStairPosition)과 같은 행을 힌트로 넘겨 "블록 바로 왼쪽, 같은 행" 칸을 고르도록 수정.
