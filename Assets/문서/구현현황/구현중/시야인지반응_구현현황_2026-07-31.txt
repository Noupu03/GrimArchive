■ 07문서 장별 구현 현황
════════════════════════════════════════════════════════════════════════
✅ 1장(적용 대상) — 인류 전파/소리감지/공격방향입력 전부 구현. 몬스터는 소리 감지만(청각보정+2칸,
   PropagationMath.SoundDetectionRange(isMonster:true)) 값 계산 가능하게 해뒀지만 실제 소비(반응)는
   대응 "역할군 AI"가 없어 미연결 — VisionMath.NonEmptyTileTempWeight와 동일한 "값만 준비, 소비자
   없음" 전례. 무리형 몬스터 전파/재전파도 동일 사유로 미구현.
✅ 2장(간접입력 종류: 전파/소리/공격방향) — 3종 전부 구현.
✅ 3장(정보 보유 구조) — 유닛별 개별 저장(Party가 아니라 Human.Propagation 컴포넌트). 직접정보
   (PerceptionRecord/PersonalMapKnowledge)와 전파정보(PropagatedInfoRecord)/일시간접입력
   (PendingSoundReaction)을 분리 저장.
✅ 4장(전파정보-직접인지 구분) — 전파는 InfoType.Indirect로만 기록되고 PersonalMapKnowledge.
   ObserveMonster의 기존 24장 PriorityRank/ShouldReplace 인프라가 직접인지로 자동 덮어써지는 걸 막는다.
🔶 5장(전파 대상 정보) — 정확 인지한 적 존재·위치(전투 합류시 RecordEnemySighting), 파티원 사망 사실
   (PartyDeathSystem), 함정/코어 확인 정보(TrapPartySystem/CorePartySystem)는 구현. 확인한 타일 정보
   일반, 조사완료결과·코어정보의 세부 필드별 전파, 상호작용 진행/취소 상태(10장 일부만 구현, 아래
   참고)는 부분적.
✅ 6장(일반 전파 조건) — PropagationSystem.CanPropagate(비전투+같은공간+카리스마기반 범위) 구현,
   PropagationMath.TryGetSpaceDistance(8방향 BFS, 코너커팅 방지, 최단경로 우회)가 1-2장 거리계산 담당.
✅ 7장(전투 진입 전파 예외) — 7-1(적 정확인지시 1회 전달+합류판정)/7-2(공격받았지만 미인지시 방향
   전파, 기존 AlertSearchState 경로에 통합)/7-3(전투 합류 예외 전파)은 7-3만 스텁(전투 중 새 아군
   합류시 "현재 인지 중인 적 정보 1회 전달" — 전투 상태 자체의 타겟 공유 개념이 코드에 없어 미구현,
   09장 참고).
✅ 8장(사망 정보 특례) — PartyDeathSystem.PropagateFrom이 이제 실제 전파조건(CanPropagate) 사용.
   TickOngoingPropagation 신설로 "그 순간 스냅샷"이 아니라 지속 재전파(03구현현황 4-13장 기존 갭)로
   교체.
✅ 9장(재전파와 정보 동기화) — InfoKnownUnits 기반 1회 전달 + 재전파(TickOngoingPropagation), 동일
   정보 중복 없음.
🔶 10장(상호작용 정보와 보호 포메이션) — 조사/함정해제/코어조사가 "실제로 시작되는" 시점에
   PropagationSystem.NotifyInteractionStarted가 1회 전파, Human.FindDirectlyVisibleInteractingAlly가
   이제 이 전파 수신 여부(HasReceivedInteractionNotice)로 참여를 게이팅 — 기존 03문서 6-1장의 "시야로
   직접 확인하면 참여"였던 근사(07 문서가 명시적으로 금지하는 방식)를 대체했다. 근사 남은 부분:
   NotifiedActiveInteractions가 유닛×상호작용유닛 단위로 한 번 전파받으면 영구 보존돼(개별 상호작용
   인스턴스 구분 없음), 같은 유닛이 나중에 별개의 상호작용을 시작할 때 범위 밖에 있었더라도 예전 전파
   기록으로 잘못 참여자격을 얻을 수 있다(드문 케이스, 판단 근거만 기재).
❌ 11장(합류 통신과 일반 정보 전파) — 합류 통신 자체는 7장/9-3장 합류판정에 녹아있지만, "장기 사실
   정보로 기록하지 않음"이라는 구분을 별도 자료구조로 명시하진 않았다(현재 구현이 이미 합류 의사를
   영구 기록하지 않는 방식이라 실질적으로는 충족).
✅ 12장(공간 판정) — PropagationMath.SameSpace(roomId 일치, 복도도 CreateMap상 별도 roomId를 가져
   그대로 커버).
✅ 13장(정보 최신성과 갱신) — 24장 인프라(WeightMath.PriorityRank/ShouldReplace) 재사용.
✅ 14장(소리 발생 구조) — 6종 전부 발생 지점 연결:
   이동음: UnitFunction.Move()
   공격실행음: SkillAction.BeginAttackCast의 pendingAttack 델리게이트(TriggerAttackVisibilityBoost와
     같은 지점 — 실제 "공격 실행" 타이밍)
   피격발생공격음/피격비명: UnitFunction.RecordHitWeightEvent(모든 물리/마법 피격 공통 경로)
   사망음: GameSession.RemoveDeadUnit(Destroy 전)
   함정작동음: TacticalFSMState.TrapPass
✅ 15장(소리로 얻는 정보) — 방향+추정지역(반경 1~2칸) 전부 PendingSoundReaction에 저장.
✅ 16장(소리 감지와 행동 반응) — 16-1(공통원칙)/16-2(이동음)/16-3(추정지역형+긴급소리 정상속도)/
   16-4(기존 행동과의 우선관계 표 — TrapResponse 전체를 소리로 게이팅, Alert가 Investigate/Wait/
   Formation보다 이미 상위라 자동 충족, JoinCombatWait는 소리 체크 자체를 안 해 자동으로 "현재 적
   대상 행동 우선")/16-5(전투 중 소리 무시 — 새 타겟 탐색 입력 활용은 전투타겟변경 시스템 부재로 스텁)
   전부 구현. 16-6(몬스터)은 위 1장 참고.
✅ 17장(공격 방향 간접입력) — AttackShape(근접/투사체/광역) 신설, SkillAction.BeginAttackCast에 파라미터
   추가(Projectile 스킬만 명시적으로 Projectile, 나머지는 기본값 Melee — 순수 지면 광역 공격 콘텐츠가
   아직 없어 AreaGround는 값만 준비된 상태). RecordHitWeightEvent의 미인식 피격 분기가 이제 인지범위+
   공격형태 두 조건을 모두 만족해야 방향을 안다고 판단하고, Propagation.PendingAttackDir에도 기록.
✅ 18장(후속 시스템 연결 표) — 아래 "다음 우선순위"에 문서가 명시한 각 연결 대상별 현재 상태 정리.

■ 03문서(탐색반응·경계·조사·함정대응) 근사치 교체 내역 — "07 문서 부재" 주석이 있던 5곳
════════════════════════════════════════════════════════════════════════
1. PartyDeathSystem.PropagateFrom — ViewDistance(spotting) 근사 → PropagationSystem.CanPropagate.
2. PartyDeathSystem — 스냅샷 1회성 전파 → TickOngoingPropagation(UnitFunction.OnUpdate 0.1초 틱)으로
   지속 재전파.
3. TrapPartySystem.OnTrapDiscovered — 파티 전체 즉시 공유 → CanPropagate 게이팅.
4. TrapPartySystem.ResolveSelection — propagationRange=ViewDistance → CanPropagate.
5. CorePartySystem.OnCoreDiscovered — 리더 즉시 공유 → TryInformLeader(CanPropagate 게이팅) +
   TickLeaderPropagation(매틱 재확인, 리더가 나중에 범위 안으로 들어오면 그때 전달). 발견자가 리더에게
   실제로 걸어가서 전파하는 물리적 이동 단계는 여전히 09_목표·이동경로 문서 몫이라 스텁(리더가 스스로
   근처로 올 때까지 늦게 알 수 있음 — 예전의 "무조건 즉시" 근사보다 07문서에 더 가깝지만, 완전한
   물리적 전파는 아님).
6.(신규 발견) Human.FindDirectlyVisibleInteractingAlly — 시야기반 참여 트리거 → 전파기반(위 10장 참고).

  대조(카리스마 전파범위 표, 소리 범위 6종, 경계감지+20 적용 순서, 몬스터청각+2, 피격비명 10%기준,
  위험도단계별 합류판정, 소리 대체 우선순위, BFS 코너커팅 우회 예시 등). Unity Test Runner로 실제
  실행은 아직 안 했다(에디터 필요) — 다음 세션 최우선 확인 대상.
- 실제 플레이 검증: 전무. 특히 아래는 실제 플레이로 반드시 확인 필요:
  1. 합류 대기(JoinCombatWait) — 위험도 2단계 몬스터를 원거리에서 발견했을 때 정말 대기하는지, 파티원이
     실제로 다가와서 합류하는지, 교착(둘 다 서로를 기다리며 멈춤) 없는지.
  2. 소리 반응 — 이동음 감지 시 실제로 방향 전환하는지, 피격비명/사망음 확인 접근이 감속 없이 정상
     속도로 이루어지는지, 함정작동음이 조사/함정해제 중에는 무시되다가 끝나면 확인하러 가는지.
  3. 보호 포메이션 참여 트리거 변경 — 예전엔 시야로만 봐도 호위했는데 이제 전파 조건을 만족해야 하므로,
     기존에 잘 되던 호위가 오히려 덜 발동하는 회귀가 없는지(특히 파티원이 흩어져 있을 때).
  4. 코어/함정/사망 정보 공유가 범위 밖 유닛에게는 안 가다가 나중에 범위 안으로 들어오면 늦게라도
