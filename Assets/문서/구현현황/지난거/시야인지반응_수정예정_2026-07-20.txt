[증상]
01-A 8장은 "정확한 인지 조건" 3가지(1.인지 범위 안 2.완전 차단 구조 뒤 아님 3.인지 성공 판정)를

하지만 UnitFunction.ForceReidentifyAttacker(02문서 4장 조건5 — 피격 시 강제 재판정, RecordHitWeightEvent

거리/각도만 맞으면 공격자 정체를 "인지 성공"으로 판정할 수 있는 구멍이 있다(실전에서는 근접 공격은

거치므로 실질적 위험은 낮지만, 08장 조건2를 문자 그대로 어기는 지점).

[해결 방향]
CastRay와 동일한 DDA 레이마칭으로 "벽 타일 / InteractableObject.IsFullyBlocking"만 확인하는 순수
LOS 체크 함수를 새로 만들어 ForceReidentifyAttacker 안에서 거리/각도 체크 다음에 호출한다.
CastRay의 확률적 부분 차단(tile.visibility 기반 "시야 흐림")은 "완전 차단 구조"가 아니므로 재현하지
않는다 — 8장 조건2가 요구하는 건 정확히 벽/IsFullyBlocking 같은 구조적 차단이다.

1) ForceReidentifyAttacker 수정(기존 메서드, 조건2 체크 한 줄 추가):
```
private void ForceReidentifyAttacker(Unit attacker)
{
	if (attacker == null) return;

	float dist = Vector2.Distance(position, attacker.position);
	float perceptionDistance = VisionMath.AwarenessDistance(spotting);
	float perceptionAngle = VisionMath.AwarenessAngle(spotting);

	Vector2 forward = GetDirVector(currentDir);
	if (forward == Vector2.zero) forward = Vector2.down;
	float centerAngle = Mathf.Atan2(forward.y, forward.x) * Mathf.Rad2Deg;
	float angleToAttackerDeg = Mathf.Atan2(attacker.position.y - position.y, attacker.position.x - position.x) * Mathf.Rad2Deg;
	bool inAngle = Mathf.Abs(Mathf.DeltaAngle(centerAngle, angleToAttackerDeg)) <= perceptionAngle / 2f;

	if (dist > perceptionDistance || !inAngle) return; // 8장 조건1: 인지 범위 밖 — 판정 자체 불가.
	if (IsFullyBlockedTowards(angleToAttackerDeg * Mathf.Deg2Rad, dist)) return; // 8장 조건2: 완전 차단 구조 뒤.

	Vector3Int tile = new Vector3Int(attacker.position.x, attacker.position.y, attacker.currentFloor);
	ForceRollPerception(attacker, attacker.GetFinalVisibility(), tile);
}
```
(주의: 기존 코드는 변수명이 `angleToAttacker`였는데 `angleToAttackerDeg`로 이름만 바꿨다 — 라디안 변환
시 헷갈리지 않기 위함. 이름을 그대로 유지하고 싶으면 `angleToAttacker * Mathf.Deg2Rad`로만 바꿔도 됨.)

2) 신규 메서드 IsFullyBlockedTowards 추가(ForceReidentifyAttacker 바로 아래에 둘 것):
```
// 01-A 8장 조건2 전용 최소 LOS 체크 — CastRay의 DDA 레이마칭과 동일한 차단 기준(벽 타일/
// InteractableObject.IsFullyBlocking)만 재현한다. 지형 밝히기/오브젝트 발견 등 CastRay의 부수효과는
// 전혀 일으키지 않는 순수 판정 함수.
private bool IsFullyBlockedTowards(float angleRad, float maxDistance)
{
	CreateMap cmap = (Session != null && Session.cmap != null) ? Session.cmap : null;
	if (cmap == null || cmap.map.floors == null) return false;
	if (currentFloor < 0 || currentFloor >= cmap.map.floors.Length) return false;
	Floor floor = cmap.map.floors[currentFloor];
	if (floor.chunks == null) return false;

	Vector2 dir = new Vector2(Mathf.Cos(angleRad), Mathf.Sin(angleRad));
	float rayPosX = position.x + 0.5f, rayPosY = position.y + 0.5f;
	int x = position.x, y = position.y;
	int stepX = dir.x > 0 ? 1 : (dir.x < 0 ? -1 : 0);
	int stepY = dir.y > 0 ? 1 : (dir.y < 0 ? -1 : 0);
	float tMaxX = dir.x != 0 ? Mathf.Abs(((dir.x > 0 ? x + 1 : x) - rayPosX) / dir.x) : float.PositiveInfinity;
	float tMaxY = dir.y != 0 ? Mathf.Abs(((dir.y > 0 ? y + 1 : y) - rayPosY) / dir.y) : float.PositiveInfinity;
	float tDeltaX = dir.x != 0 ? Mathf.Abs(1f / dir.x) : float.PositiveInfinity;
	float tDeltaY = dir.y != 0 ? Mathf.Abs(1f / dir.y) : float.PositiveInfinity;

	int mapWidth = floor.config.width * 8;
	int mapHeight = floor.config.height * 8;
	float dist = 0f;

	while (dist < maxDistance)
	{
		if (tMaxX < tMaxY) { dist = tMaxX; tMaxX += tDeltaX; x += stepX; }
		else { dist = tMaxY; tMaxY += tDeltaY; y += stepY; }
		if (dist >= maxDistance) break; // 공격자 자신이 서 있는 타일은 차단 판정에서 제외.

		if (x < 0 || x >= mapWidth || y < 0 || y >= mapHeight) return true;
		int cx = x / 8, tx = x % 8, cy = y / 8, ty = y % 8;
		if (cx < 0 || cx >= floor.config.width || cy < 0 || cy >= floor.config.height) return true;
		Chunks c = floor.chunks[cx, cy];
		if (c.roomId == -1 || c.chunk == null) return true;

		Tile tile = c.chunk[tx, ty];
		if (tile.name == "Wall" || tile.isStructureExist) return true;

		Vector3Int tilePos = new Vector3Int(x, y, currentFloor);
		if (Session != null && Session.objectGrid.TryGetValue(tilePos, out InteractableObject blocker) &&
			!blocker.IsCollected && blocker.IsFullyBlocking)
		{
			return true;
		}
	}
	return false;
}
```

3) UnitFunction.cs — ResolveReachedTarget/ForceRollPerception에 kind 매개변수 추가:
```
private PerceptionOutcome ResolveReachedTarget(object key, float targetVisibility, Vector3Int tile, float dist, PerceptionTargetKind kind, out bool firstTouchThisPass)
{
	firstTouchThisPass = !_reachedPerceptionThisPass.ContainsKey(key);
	_reachedPerceptionThisPass[key] = (dist, tile);
	if (!firstTouchThisPass)
		return perceptionRecords.TryGetValue(key, out var already) ? already.Outcome : PerceptionOutcome.Unrecognized;

	perceptionRecords.TryGetValue(key, out var existing);
	bool isNewOrReentering = existing == null || !existing.WasInRange;
	bool suspiciousReapproach = existing != null && existing.PendingSuspiciousInvestigation
		&& dist <= PerceptionMath.SuspiciousTileReapproachDistanceTiles;

	if (isNewOrReentering || suspiciousReapproach)
		return ForceRollPerception(key, targetVisibility, tile, kind);

	existing.WasInRange = true;
	existing.LastKnownTile = tile;
	return existing.Outcome;
}

private PerceptionOutcome ForceRollPerception(object key, float targetVisibility, Vector3Int tile, PerceptionTargetKind kind)
{
	if (!CanPerceive)
	{
		if (!perceptionRecords.TryGetValue(key, out var frozen))
		{
			frozen = new PerceptionRecord();
			perceptionRecords[key] = frozen;
		}
		frozen.WasInRange = true;
		frozen.LastKnownTile = tile;
		frozen.TargetKind = kind;
		return frozen.Outcome;
	}

	float detectionCorrection = PerceptionMath.DetectionCorrection(spotting, IsAlert);
	float mentalCorrection = GetMentalVisibilityCorrection();
	float total = PerceptionMath.TotalPerceptionVisibility(targetVisibility, detectionCorrection, mentalCorrection);
	PerceptionOutcome outcome = PerceptionMath.RollOutcome(total, Random.value);

	if (!perceptionRecords.TryGetValue(key, out var record))
	{
		record = new PerceptionRecord();
		perceptionRecords[key] = record;
	}
	bool nowSuspicious = outcome == PerceptionOutcome.SuspiciousTile;
	NotifyPerceptionSuspiciousChanged(record.PendingSuspiciousInvestigation, nowSuspicious);
	record.Outcome = outcome;
	record.WasInRange = true;
	record.LastKnownTile = tile;
	record.TargetKind = kind;
	record.PendingSuspiciousInvestigation = nowSuspicious;
	return outcome;
}
```

된다"(0순위, 표 밖 특례)를 서로 다른 두 개념으로 구분해서 쓴다. 그런데 이 코드베이스는 "공격 대상"
개념 자체가 playerAttackTarget 하나뿐이라서, 그 필드가 원래 문서상 어느 쪽에 해당하는지가 실제로
갈린다:
- 4순위(현재 그대로) 해석: "공격 대상이 있다"는 사실 자체를 가리키는 표현으로 보고, 그 대상이
  어떻게 정해졌는지(플레이어 클릭이든 AI 자동 선택이든)는 안 따진다.
- 0순위 해석: playerAttackTarget은 이름 그대로도, 실제 유일한 세터(InputManager)로도, Goals.cs의
  주석으로도 명백히 "플레이어가 내린 명령"이라서 10장의 "플레이어 명령 → 항상 최우선" 특례를
  그대로 적용해야 한다.

[실제 동작 차이]
지금(4순위)은 스킬 사용 중(1순위)이거나 1칸 이내 근접 대상이 있으면(3순위) 플레이어가 다른 대상을
공격하라고 명령해도 시야가 그쪽을 보지 않는다. 0순위로 바꾸면 플레이어 명령이 항상 이긴다 — 유닛이
스킬을 쓰는 중이든 다른 적과 붙어있든 상관없이 즉시 플레이어가 지정한 대상 쪽을 본다.

[선택지]
A. 0순위로 재분류 — ResolveVisionDirection()의 해당 후보 등록을 `VisionDirectionReason.
   CurrentAttackTarget` 대신 `VisionDirectionReason.PlayerCommand`로 바꾼다(한 줄 수정). 10장
   문구("플레이어의 명령... 항상 최우선")를 문자 그대로 따르는 해석.
B. 4순위 유지 — 지금 그대로 둔다. "현재 공격 대상 존재"를 대상의 출처와 무관한 상태 서술로 보는
   해석. 코드 변경 없음.
어느 쪽이든 한 줄짜리 변경(또는 무변경)이라 다른 작업자와 겹칠 위험은 낮지만, 판단 자체가 우선
필요해서 항목 1/2와 달리 시안만 적어두고 코드는 건드리지 않았다.

■ 항목 5(2026-07-20 정정): 02문서 2장/4장 — 오브젝트는 한 번 정확 인지되면 다시는 재판정을 안 받음
          (현재는 무해, 함정 엔티티 생기는 순간 문제됨)
════════════════════════════════════════════════════════════════════════
[최초 설명이 부정확했던 부분 — 가중치 문서 15장 검증 중 재확인하며 정정]
처음엔 "오브젝트 위험도가 인지 게이팅을 전혀 안 받는다"고 적었는데, 다시 보니 부정확하다.
`_objectDanger[objectId]`는 `PersonalMapKnowledge.RegisterObject()` 안에서만 세팅되고,
`RegisterObject()`는 `UnitFunction.CastRay`에서 `outcome == PerceptionOutcome.AccuratePerception`
일 때만 호출된다 — **최초 등록 시점엔 정확 인지 게이팅이 이미 정확히 걸려 있다.**

진짜 문제는 CastRay의 오브젝트 판정 블록 자체가 이 조건 안에서만 실행된다는 것이다:
```
if (!obj.IsCollected && !terrainObserver.personalMap.IsObjectKnown(obj.Id))
{
    if (inPerceptionRange) { ... ResolveReachedTarget(...) ... }
}
```
`IsObjectKnown(obj.Id)`가 true가 되는 순간(=한 번이라도 정확 인지에 성공한 순간) 이 블록 자체가
영원히 스킵된다 — 즉 오브젝트는 유닛과 달리 02문서 4장의 재진입/재접근 트리거를 다시 받을 방법이
아예 없다. "미인식 상태에서도 위험도가 반영된다"가 아니라 **"한 번 알려지면 다시 미인식으로
돌아갈 수 있는 경로 자체가 없다"**가 정확한 설명이다. 결과적으로 보이는 증상(함정처럼 위험한
오브젝트의 위험도가 사실상 영구 고정된다는 것)은 비슷하지만 원인이 다르다.

[왜 지금은 무해한가 — 기존 설명과 동일]
현재 스폰되는 모든 오브젝트(시체/전멸흔적/루팅)는 baseDanger를 명시적으로 0f로 넘긴다
(GameSession.RemoveDeadUnit/CheckPartyWaveState 확인 완료) — 그래서 objectDanger 항이 항상 0이라
실제로 안전 판정에 영향을 준 적이 없다. 함정처럼 baseDanger>0인 오브젝트가 생기면, 딱 한 번
정확 인지에 성공하는 순간 그 위험도가 영구 고정된다(이후 관찰자가 그 위치를 다시 봐도 재판정
자체가 없으므로 낮아지거나 사라질 방법이 없다).

[수정 방향 — 함정 엔티티가 생길 때 같이 고려할 것]
함정 엔티티가 없어 지금 구체적인 코드를 제안하기는 이르다. 방향성만 남긴다:
- 오브젝트도 유닛처럼 `IsObjectKnown` 여부와 무관하게 CastRay가 매 패스 `ResolveReachedTarget`을
  호출하도록 바꾸고(단, 등록 부수효과는 firstTouch && AccuratePerception일 때만 여전히 게이팅),
  02문서 4장의 트리거 조건(재진입/재접근/피격)을 오브젝트에도 동일하게 적용하는 게 가장 정직한
  해법이다. `IsObjectKnown`은 "RegisterObject를 다시 호출하지 않기 위한 가드"로만 남기고, "판정
  자체를 스킵하는 가드"에서는 빼야 한다.
- 함정은 대부분 "발견 즉시 등록"이라 발견 전엔 애초에 RegisterObject가 안 불려서 objectDanger 자체가
  안 잡힐 가능성도 있다 — 함정 엔티티/판정 흐름을 설계할 때 이 경로부터 먼저 확인할 것.

■ 항목 6: 02문서 5장 — 안전 확인(일반 타일) 타이머가 CanPerceive(인지 판정 불가 상태) 게이팅을 안 받음
════════════════════════════════════════════════════════════════════════
[발견 경위]
02문서 5장 조건3("관찰자가 인지 판정을 수행할 수 있는 상태임" — 기절/수면/마비/행동불능이면 인지
판정 불가)은 2장이 "미확인 일반 타일"도 명시적으로 인지 판정 대상에 포함시키므로, 일반 타일
안전 확인에도 당연히 적용돼야 한다. 실제 유닛/오브젝트 판정 경로(UnitFunction.CastRay →
ResolveReachedTarget → ForceRollPerception)는 CanPerceive 가드가 이미 걸려 있다(이번 검증 라운드
초반에 한 곳으로 중앙화 완료, 이미 반영됨 — 롤백 대상 아님). 그런데 안전 확인(TickTileSafety/
TickTileInterestConfirm) 쪽은 이 가드가 전혀 없다:
```
// UnitFunction.OnUpdate, 현재 코드
if (this is Human human && Session != null)
{
	foreach (var tile in human.personalMap.KnownDangerTiles.ToList())
	{
		bool threatPresent = Session.unitGrid.TryGetValue(tile, out Unit occupant) && occupant is Monster
			&& occupant.hp > 0f && human.personalSpottedEnemies.Contains(occupant);
		human.personalMap.TickTileSafety(tile, threatPresent, deltaTime);
	}

	foreach (var tile in human.personalMap.KnownInterestTiles.ToList())
	{
		human.personalMap.TickTileInterestConfirm(tile, deltaTime);
	}
}
```
기절한 인류 유닛도 이미 추적 중인 위험/흥미 타일의 안전 확인 타이머가 실시간(deltaTime)으로 계속
흘러간다 — 조건3 위반. 이건 함정 엔티티 같은 미래 의존성이 없어 스턴 상태이상이 이미 존재하는
지금도 실제로 관측 가능한 문제다(기절한 유닛 옆에 몬스터가 있다가 사라지면, 그 유닛이 기절해
있는 동안에도 안전 확인 타이머가 흘러 위험도가 감쇠된다).

[제안 코드]
if 조건에 CanPerceive만 추가하면 된다:
```
if (this is Human human && Session != null && CanPerceive)
{
	foreach (var tile in human.personalMap.KnownDangerTiles.ToList())
	{
		bool threatPresent = Session.unitGrid.TryGetValue(tile, out Unit occupant) && occupant is Monster
			&& occupant.hp > 0f && human.personalSpottedEnemies.Contains(occupant);
		human.personalMap.TickTileSafety(tile, threatPresent, deltaTime);
	}

	foreach (var tile in human.personalMap.KnownInterestTiles.ToList())
	{
		human.personalMap.TickTileInterestConfirm(tile, deltaTime);
	}
}
```
CanPerceive는 이미 Unit.cs에 공개 프로퍼티로 있어(`public bool CanPerceive => stunDuration <= 0f;`)
그대로 참조하면 된다. 다른 항목들과 달리 UnitFunction.OnUpdate의 이 블록 하나만 건드리는 국소적
변경이라 항목 1/2(같은 파일의 다른 메서드)와 겹칠 위험은 낮아 보인다.

■ 항목 7: 02문서 10장 — 경계 상태 감지 보정(+20)이 인지 판정에만 적용되고 시야/인지 거리·인지각엔
          미적용
════════════════════════════════════════════════════════════════════════
[발견 경위]
10장: "경계 중 감지 보정 = 감지 스탯 + 20. 이 값은 인지 판정뿐 아니라 시야 거리, 인지 거리, 인지각에도
반영된다." 확인 결과 인지 판정(확률 굴리기) 쪽에는 이미 정확히 적용돼 있다:
```
// ForceRollPerception 안
float detectionCorrection = PerceptionMath.DetectionCorrection(spotting, IsAlert); // +20 반영됨
```
하지만 시야 거리/인지 거리/인지각을 계산하는 두 곳은 여전히 raw spotting만 쓴다:
```
// UpdateFOV, 라인 590~594 부근
float viewAngle          = VisionMath.BaseViewAngleDeg;
float viewDistance       = VisionMath.ViewDistance(spotting);        // +20 미반영
float perceptionAngle    = VisionMath.AwarenessAngle(spotting);      // +20 미반영
float perceptionDistance = VisionMath.AwarenessDistance(spotting);   // +20 미반영
```
```
// ForceReidentifyAttacker, 라인 114~116 부근
float dist = Vector2.Distance(position, attacker.position);
float perceptionDistance = VisionMath.AwarenessDistance(spotting);   // +20 미반영
float perceptionAngle = VisionMath.AwarenessAngle(spotting);         // +20 미반영
```

[처음엔 왜 안 했는지 / 지금은 왜 쉬워졌는지]
02문서 최초 구현 당시엔 "경계 상태를 시야 범위 자체에 반영하려면 별도 상태 전파 경로가 필요하다"고
판단해서 미뤘다(구현현황 문서에 그렇게 기록돼 있음). 그런데 그 뒤 성능 이슈를 고치면서
Unit.IsAlert가 이미 O(1) 프로퍼티로 존재하게 됐다 — 지금은 "새 상태 전파 경로"가 필요 없고, 그냥
IsAlert를 한 번 더 읽어서 spotting에 더해주기만 하면 된다.

[제안 코드]
1) UpdateFOV 수정:
```
float viewAngle          = VisionMath.BaseViewAngleDeg;
float effectiveSpotting  = spotting + (IsAlert ? PerceptionMath.AlertDetectionBonus : 0f); // 10장: 경계 중 감지 보정
float viewDistance       = VisionMath.ViewDistance(effectiveSpotting);
float perceptionAngle    = VisionMath.AwarenessAngle(effectiveSpotting);
float perceptionDistance = VisionMath.AwarenessDistance(effectiveSpotting);
```
2) ForceReidentifyAttacker 수정:
```
float dist = Vector2.Distance(position, attacker.position);
float effectiveSpotting = spotting + (IsAlert ? PerceptionMath.AlertDetectionBonus : 0f);
float perceptionDistance = VisionMath.AwarenessDistance(effectiveSpotting);
float perceptionAngle = VisionMath.AwarenessAngle(effectiveSpotting);
```
(나머지 로직은 그대로 — perceptionAngle/perceptionDistance를 쓰는 아래 코드는 안 바꿔도 됨)

[참고] PerceptionMath.AlertDetectionBonus는 이미 public const로 존재(값 20f) — 새로 만들 것 없음.
