■ 추가 수정(2026-07-20, 같은 날 성능 이슈 리포트로 발견) — perceptionRecords 무한 성장 + IsAlert O(n)
════════════════════════════════════════════════════════════════════════
02문서 구현 직후 "프레임이 5까지 떨어진다"는 리포트를 받고 확인한 결과, 이번에 새로 만든
Unit.perceptionRecords가 원인이었다. 두 가지가 겹쳐서 문제가 됐다:
1. perceptionRecords는 "이 관찰자가 본 적 있는 대상"을 유닛이 죽거나 오브젝트가 사라져도 지우지
   않는 구조였다 — 웨이브가 반복될수록 죽은 몬스터에 대한 destroyed 참조가 관찰자마다 계속 쌓였다.
2. Unit.IsAlert가 이 딕셔너리 전체를 매번 순회(O(n))했는데, 이 프로퍼티를 읽는
   UnitFunction.ForceRollPerception이 "피격마다 무조건 재판정"하는 IsAttackerIdentified(17장 게이팅)
   경로에서 매 타격마다 호출된다 — 즉 웨이브를 거듭할수록 커지는 n에 대해 전투 중 타격마다 O(n)
   스캔이 반복되는 구조였다. 세션 초반엔 안 느껴지다가 웨이브가 여러 번 돌고 나면 급격히 무거워지는
   패턴과 "갑자기 5프레임" 증상이 정확히 들어맞는다.
수정:
- Unit.IsAlert를 O(n) 순회 대신 _alertRecordCount(카운터) 기반 O(1) 프로퍼티로 교체.
  PendingSuspiciousInvestigation이 바뀌는 유일한 지점(UnitFunction.ForceRollPerception)에서
  Unit.NotifyPerceptionSuspiciousChanged(old,new)로 카운터를 갱신.
- GameSession.RemoveDeadUnit/DespawnUnit에 ClearPerceptionRecordsFor(dead) 추가 — 유닛이 죽는
  시점(사망은 매 프레임 일어나지 않으므로 O(units) 비용을 여기서 감당)에 전 유닛의
  perceptionRecords에서 그 유닛에 대한 기록을 Unit.RemovePerceptionRecord()로 제거한다.
참고(이번엔 안 건드림, 낮은 우선순위): 오브젝트(전리품/시체/전멸흔적) 회수·파괴 시에도 발견자의
perceptionRecords에 obj.Id 항목이 그대로 남는다 — 다만 이건 "유닛당 한 번 본 대상 전체"가 아니라
"세션 동안 스폰된 오브젝트 총수"에 비례해서 유닛 사망 케이스보다 훨씬 작게 자란다. PersonalMapKnowledge.
OnObjectCollected/OnObjectDestroyed 호출 지점에서 같은 방식으로 정리할 수 있음.

■ 검증 단계 발견/수정(2026-07-20, "항목별로 확인해봐" 요청에 따른 재검토에서 발견)
════════════════════════════════════════════════════════════════════════
02문서 구현 내용을 장별로 코드와 다시 대조하는 과정에서 실제 동작에 영향을 주는 결함 3개를 찾아
그 자리에서 고쳤다(전부 UnitFunction.cs):

1. [13장/23장] 안전 확인이 "정확 인지" 대신 "물리적 점유"만 봤던 문제 — OnUpdate의 TickTileSafety
   호출에서 threatPresent를 `Session.unitGrid`(그 타일에 몬스터가 물리적으로 있는지)만으로 계산하고
   있었다. 23장은 "인지 판정 결과가 미인식이면 실제로 유닛이 존재해도 안전타일로 인지된다"고 명시하는데,
   기존 코드는 미인식 판정이 나온 몬스터도 "물리적으로 있으니 위험"으로 계속 취급해 안전 확인 타이머가
   리셋되고 있었다 — 02문서 없이 만들어진 기존 근사(07-13 시점엔 "이미 이 근사로 구현해 뒀다"고만
   적어뒀던 부분)가 02문서가 생기면서 정확히 무엇이 부족한지 확정됐다. `human.personalSpottedEnemies.
   Contains(occupant)`를 추가 조건으로 걸어 "물리적으로 있음 + 지금 정확 인지 중임" 둘 다 확인하도록
   수정 — personalSpottedEnemies는 이제 AccuratePerception된 대상만 담으므로(4장 구현) 정확히 23장
   규칙과 맞아떨어진다.
2. [4장 조건5/17장] 피격 시 강제 재판정이 인류 피해자에게만 걸렸던 문제 — 원래 IsAttackerIdentified가
   "재판정 수행"과 "가중치 이벤트 게이팅 여부 결정"을 한 함수에서 같이 하면서 `if (!(this is Human))
   return true;`로 조기 종료해, 몬스터가 인류에게 맞았을 때는 4장 조건5(피격 시 재판정)이 아예
   실행되지 않았다. 26장은 "인지 판정" 자체는 인류/몬스터 공통이라고 명시하므로(가중치 이벤트 게이팅만
   인류 전용), 재판정 로직을 ForceReidentifyAttacker로 분리해 종족 무관하게 항상 실행하고,
   IsAttackerIdentified는 그 결과를 "인류만" 가중치 이벤트에 쓸지 판단하는 순수 게이팅 함수로 남겼다.
3. [5장] 기절 상태에서도 피격 시 강제 재판정이 확률표를 굴렸던 문제 — ResolveReachedTarget(평상시
   경로)은 CanPerceive를 확인했지만, ForceRollPerception을 직접 부르는 피격 강제 재판정 경로(옛
   IsAttackerIdentified)는 이 가드를 거치지 않아 기절한 유닛도 피격당하면 정상적으로 공격자를 인지
   판정할 수 있었다 — 5장 "기절: 인지 판정 불가"에 위배. CanPerceive 가드를 ForceRollPerception
   내부로 옮겨 모든 호출 경로(트리거 재판정/강제 재판정)에 한 번에 적용되도록 정리했다(ResolveReachedTarget
   쪽 중복 가드는 제거).

테스트 코드도 하나 더 안전하게 고쳤다: PerceptionSystemTests.cs의 OutcomeProbabilities_Table이
ValueTuple을 Assert.AreEqual(object,object)로 직접 비교하고 있었는데, NUnit 버전에 따라 튜플 구조적
비교 지원이 갈릴 수 있어 성분별 비교(AssertProbabilities 헬퍼)로 바꿨다 — 값 자체는 원래도 맞았지만
테스트 신뢰도 문제였다.
